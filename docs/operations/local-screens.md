# 화면을 실제 서버로 보기

화면(`web/`)의 시험은 서버를 부르지 않는다(가짜 `fetch`). 실제 서버에 붙여 끝까지 보는 것은 PC 의 compose 로 손으로 한다.
끝에서 끝까지의 자동 시험(Playwright)은 이 문서의 "한 판 따라가기"가 손으로 한 번 돈 뒤에 CI 의 stack 에 붙인다(`docs/product/screens.md` 의 "시작할 때 정한 것").

공개된 시나리오와 계정 둘이 있어야 탐색, 로비, 테이블 방, 스트림을 볼 수 있다. 시나리오를 만드는 화면(B9)이 아직 없으므로
`tools/dev_seed.py` 가 시험 계정 둘, 공개된 견본 시나리오(맵, 물건, 인물, 퀘스트가 있다), 로비에 보이는 견본 테이블을 한 번에 채운다.

## 띄우고 채우기

저장소 루트에서. `.env` 는 [루트 README 의 실행](../../README.md#실행)대로 만들어 둔다.
한 판을 돌려 보려면 루트 `.env` 에 한 줄을 더 적는다. 견본 계정은 크레딧이 없어서, 결제 서버에 붙어 있으면 첫 라운드부터 서술하지 않는다
(크레딧이 모자란 사람을 기다리다 5분 뒤 자리에서 뺀다).

```
GAME_BILLING_URL=
```

빈 값이면 게임 서버가 서술 값을 받지 않는다(결제 서버 없는 모드). 결제와 크레딧이 모자랄 때의 화면을 볼 때는 이 줄을 지운다.

```powershell
docker compose --profile app up -d --build
docker compose --profile app exec trpg-server python -m scripts.models sync
docker compose --profile app exec trpg-server python -m scripts.models list
docker compose --profile app exec trpg-server python -m scripts.models enable <list 에서 고른 이름표>
uv run --no-project python tools/dev_seed.py
```

- 서술 모델은 하나 이상 켜 둔다. 시나리오를 만들려면 추천 서술 모델이 있어야 한다. 모델이 없으면 `dev_seed.py` 가 위의 명령을 알린다.
- 서술은 처음에 가짜다(`trpg-server/.env` 의 `NARRATOR` 가 비었거나 `fake`). AI 를 부르지 않고 "[n 라운드의 결과]"와 각자 한 일을 한 줄씩 늘어놓는다.
  화면의 흐름을 보는 데는 이것으로 된다. 모델의 글과 미리 보기를 보려면 `NARRATOR=llm` 과 `LLM_MODEL` 을 적고 `docker compose --profile app up -d trpg-server` 로 다시 띄운다.
- `dev_seed.py` 는 두 계정을 가짜 본인확인 업체로 본인인증한다(성년). 그래서 지갑의 충전(시험용 결제창)을 할 수 있고, 환영 실버를 받는다.
- `dev_seed.py` 는 몇 번 돌려도 같다. 시나리오와 테이블은 이미 있으면 만들지 않고, 계정은 비밀번호만 다시 정한다.
  맵이나 화폐가 없는 앞의 견본이 있으면 세계를 넣고 새 판을 게시한다. 그 판으로 연 모집 중인 테이블이 없으면 새로 연다(앞의 테이블은 그대로 둔다).
  개발 환경(`APP_ENVIRONMENT=development`)이 아니면 계정을 만들지 않고 멈춘다. 이 PC 의 주소(127.0.0.1, localhost)만 받는다.
- 화면은 `http://127.0.0.1:8080` 이다(프록시의 이미지에 담긴 것). 화면을 고쳤으면 `docker compose --profile app up -d --build proxy`.
  개발 서버(`npm run dev`, 5173)로 볼 때는 [web/README.md 의 실행](../../web/README.md#실행)의 출처 설정을 한다.

## 견본의 세계

`tools/dev_seed_world.py` 에 있다. 행동마다 쓸 거리를 하나씩 둔다. 룰은 SRD5 템플릿이다.

| 거리 | 무엇 |
| --- | --- |
| 장소와 길 | 수도원 문(시작) ↔ 회랑(5분) ↔ 부엌(3분), 회랑 ↔ 종탑(10분). 부엌 ↔ 지하 저장고(2분)는 숨긴 길이다(지혜 보통으로 찾는다) |
| 놓인 물건 | 수도원 문에 횃불 둘. 지하 저장고에 숨긴 은 성배(지능 쉬움으로 찾는다) |
| 시작 소지품 | 모두 약초 하나(가벼움 1d4 회복). 프리젠 렌은 약초 하나 더, 미라는 횃불 |
| 인물 | 늙은 문지기(진짜 이름 마르타). 경계한다. 녹슨 열쇠를 품에 지녔다. 들키면 적대하고, 맞서면 등불을 휘두른다. 떠돌이 행상은 상인이다(약초 5, 횃불 3을 판다). 둘 다 스타팅에 나와 첫 장면부터 고를 수 있다 |
| 돈 | 화폐는 은화(닢). 모두 20닢으로 시작하고 프리젠 도르는 15닢을 더 받는다. 값은 약초 6, 횃불 3, 은 성배 120(녹슨 열쇠는 사고팔지 못한다). 행상은 값의 절반에 사 준다. 퀘스트를 이루면 저마다 30닢 |
| 퀘스트 | 울리지 않는 종. 처음부터 보인다. 종탑에 닿으면 이룬다. 보상은 30닢 |
| 캐릭터 | 프리젠 셋, 직접 쓰기, 직접 적기, 점수제(27), 주사위(4d6 높은 셋). 최대 HP 는 8 에 건강의 보정, 20 까지. 방장이 "한 번 더"를 줄 수 있다 |
| 시계 | 1일째 22시에 시작한다. 라운드마다 10분이 흐른다 |

## 로그인

- 계정은 `seed_host`(방장)와 `seed_guest`(손님)이다. 비밀번호는 `dev_seed.py` 가 찍는다(기본 `seed-pass-2026`).
- 로그인은 두 단계다. 메일 서버를 적지 않았으면 코드가 메일 대신 로그에 찍힌다: `docker compose --profile app logs -f auth-mail`
- 두 계정을 함께 보려면 다른 브라우저나 시크릿 창을 쓴다. 같은 브라우저의 창은 refresh 쿠키를 나눠 한 사람으로 보인다.

## 한 판 따라가기

두 창(방장, 손님)으로 한다. 각 단계의 "보일 것"이 다르면 그 화면과 서버의 응답(브라우저의 네트워크 탭)을 남겨 둔다.

| 단계 | 할 것 | 보일 것 |
| --- | --- | --- |
| 1. 들어가기 | 방장은 `dev_seed.py` 가 찍은 테이블 주소로, 손님은 로비에서 `[견본] 목요일 모임`에 들어간다 | 두 창의 앉은 사람과 채팅이 서로 바로 바뀐다 |
| 2. 캐릭터 | 방장은 프리젠 "수도사 렌", 손님은 "주사위로 굴린 점수 놓기"로 굴리고 놓는다 | 굴린 눈과 점수, 다른 능력치가 쓴 점수는 막힘. 상대의 캐릭터는 15초 안에 보인다(이벤트가 없어 읽기로 따라간다) |
| 3. 시작 | 방장이 시작한다 | 1라운드의 장면(스타팅), 상태 패널의 HP·약초·퀘스트 "울리지 않는 종"·"1일째 22:00 · 밤"·지금 있는 곳 "수도원 문"과 놓인 횃불 |
| 4. 1라운드 | 방장: 행동 "판정" → 공격 → 대상 "늙은 문지기", 피해 가벼움. 손님: 소지품의 "약초 건네기" → 받을 사람 렌 | 마감 전에는 상대의 선언이 "선언을 냈습니다"로만 보인다. 둘 다 내면 결과(판정 줄, 문지기 피해, 건넨 것)와 서술, 2라운드 |
| 5. 2라운드 | 방장: "지목" → 이름 "마르타", 누구 "늙은 문지기". 손님: 놓인 횃불 "줍기", 글에 "행상에게 눈짓한다"처럼 행상을 넣는다(가짜 서술은 선언의 글을 그대로 다음 장면으로 쓰고, 장면에 나온 인물만 고를 수 있다) | "맞혔습니다: 마르타", 그 뒤 장면의 인물 이름이 마르타로 바뀐다. 손님의 소지품에 횃불 |
| 5-1. 사고팔기 | 방장: "사기" → 상인 "떠돌이 행상", 횃불 2개. 손님: 5에서 주운 횃불의 "팔기"(상인이 채워진다) | 칸 아래 "낼 돈 6닢 · 가진 돈 20닢". 결과 "횃불 ×2 샀습니다(낸 돈 6닢, 남은 돈 14닢)", 손님은 "받을 돈 1닢"(3닢의 절반을 내림). 소지품 탭의 돈이 바뀐다 |
| 5-2. 돈 건네기 | 방장이 소지품 탭의 돈 "건네기" → 받을 사람 손님, 5닢 | 다음 라운드에 두 사람의 돈이 바뀌고, 일어난 일(L)에 "…: 5닢 → …" |
| 6. 이동 | 둘 다 "회랑 가기", 다음 라운드에 "부엌 가기" | 지금 있는 곳과 갈 수 있는 곳이 바뀐다. 시각이 라운드마다 흐른다 |
| 7. 찾기 | 부엌에서 "찾기" | 성공하면 지하 저장고 쪽 길이 갈 수 있는 곳에 생긴다. 실패하면 다음 라운드에 다시 |
| 8. 숨긴 물건 | 지하 저장고로 가서 "찾기", 은 성배 "줍기" | 찾으면 은 성배를 바로 갖는다(찾은 사람의 소지품) |
| 9. 퀘스트 | 종탑으로 간다 | 상태 패널의 퀘스트가 "성공" |
| 10. 방장의 닫기 | 한 사람만 선언하고 방장이 "라운드 닫기" | 선언하지 않은 사람을 기다리지 않고 닫힌다 |
| 11. 끊김 | 선언을 받는 중에 `docker compose --profile app restart trpg-server` | 몇 초 안에 다시 붙고("연결이 끊겨 n초 뒤에 다시 붙습니다"), 그동안의 채팅이 빠지지 않는다 |

## 볼 것

화면마다 만든 PR 의 "알아 둘 것"에서 실제 서버로 보지 못한 것을 모았다. "한 판 따라가기"에 없는 것만 적는다.

| 화면 | 볼 것 |
| --- | --- |
| 로그인, 첫 화면(A1, A2) | 로그인 두 단계, 새로 고침 뒤에도 로그인이 남는가(refresh), 첫 화면의 이어하기와 공개 목록 |
| 가입, 비밀번호(A2) | 가입 세 단계와 동의, 비밀번호 재설정 메일의 링크(`PASSWORD_RESET_URL` 을 `http://localhost:8080/reset-password` 로) |
| 지갑(A6) | 머리의 "골드 0 · 실버 0", 지갑의 빈 내역. 결제를 켜고(`GAME_BILLING_URL` 줄을 지움) 크레딧을 넣은 계정으로 한 라운드를 돌리면 내역에 "서술 값 대기"가 생기고 다음 라운드가 열리면 "서술 값 사용"으로 바뀌는가, 머리의 잔액이 따라 바뀌는가. `docker compose stop billing-server` 뒤 머리의 잔액이 사라지고 지갑에 다시 시도가 보이는가 |
| 충전(A7) | 지갑의 "충전하기" → 상품 → 시험용 결제창의 "결제 성공"이면 머리의 골드가 늘고 내역에 "충전". "카드 거절"이면 돈이 나가지 않았다는 글. "답이 오지 않음"이면 확인 중 → "다시 확인"으로 승인. `docker compose stop billing-server` 로 결제를 누른 뒤의 다시 보내기. 결제를 켠 채(`GAME_BILLING_URL` 지움) 크레딧이 모자란 라운드의 알림에 "충전하기"가 붙는가 |
| 주문 내역(A8) | 충전한 주문이 "충전됨"과 청약철회 기한으로 보이는가. 그 골드로 서술 값을 내기 전에는 "청약철회" → 확인 → "환불됨", 지갑에 "환불" 줄. 서술 값을 낸 뒤에는 "골드를 썼거나…"로 막히는가. 결제창만 열고 닫은 주문이 "치르지 않은 주문도 보기"로만 보이는가 |
| 마이페이지(A5) | 계정, 비밀번호 바꾸기(다른 창이 로그아웃되는가), 모든 기기 로그아웃, 선택 동의 켜고 끄기 |
| 탐색, 소개(B1, B2) | 견본이 보이는가, 장르·인원·태그로 거르기, 만든 사람의 이름, 로그인 전후(추천 모델의 이름) |
| 테이블 만들기, 로비(B3, B4) | 만들기의 자세한 설정과 모델의 값, 비밀번호 테이블, 초대 코드 |
| 캐릭터(B5) | 점수제의 총점, 직접 적기의 범위, 바꾸기, 같은 프리젠을 두 창에서 함께 고르기(나중 사람에게 "그 사이에 다른 사람이 가져간") |
| 방장의 운영(B6 ⑤) | 손님을 내보내면 손님 창이 "앉아 있지 않거나 없는 테이블"로 바뀌는가, 새 초대 코드로 다시 들어오기, 방장 넘기기 뒤 두 창의 "방장" 패널, 끝내기 뒤 두 창, 손님의 주사위에 "한 번 더 굴리기" |
| 라운드(B6) | 마감 시간이 있는 테이블의 남은 시간과 마감 뒤 닫힘, 서술 실패 뒤 방장의 "서술 다시 맡기기"(`NARRATOR=llm` 에 없는 모델) |
| 결제를 켰을 때 | `GAME_BILLING_URL` 줄을 지우고 다시 띄우면 첫 라운드에서 서술하지 않는다. 지금 라운드 위에 "…: 크레딧이 모자라 서술하지 못합니다"가 두 창에 뜨고, 기다리는 시간이 지나면 "자리에서 빠졌습니다"(일어난 일의 탭에도) |
| 일어난 일(B6 ④-2) | 한 판을 따라가며 `L` 탭에 물건, 이동, HP, 퀘스트가 한 줄씩 쌓이는가. 끊겼다 다시 붙은 뒤에 같은 줄이 두 번 보이지 않는가. 방장이 모델이나 설정을 바꾸면 "서술 모델: …" 같은 줄이 두 창에 생기는가 |

## 지우기

견본은 보통의 데이터다. 처음부터 다시 하려면 볼륨째 지운다(모든 로컬 데이터가 지워진다).

```powershell
docker compose --profile app down -v
```
