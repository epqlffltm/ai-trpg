# AI 캐릭터 챗 서비스 조사

AI 챗과 이야기형 서비스를 설계하기 전에, 다른 서비스가 **캐릭터를 어떻게 만들게 하는지**와 **어떻게 돈을 받는지**를 본 기록이다.

- 조사일: 2026-10-14 (국내 서비스), 2026-10-18 (해외 서비스 보충)
- **믿을 수 있는 정도.** 국내 서비스는 사용자가 쓴 위키 문서(나무위키 35건)와 기사에서 읽었다. 가격과 글자 수는 자주 바뀌고 문서마다 시점이 다르다. 설계의 방향을 잡는 데 쓰고 숫자를 그대로 옮기지 않는다.
  해외 서비스는 비교 블로그에서 기능 목록만 가져왔다. 홍보 성격이 있어 기능의 유무만 참고한다.
- **읽지 못한 것.** zeta(애플리케이션)와 일부 서비스의 문서는 열리지 않았거나 거의 비어 있다. 선톡, 기억, 음성은 제타·크랙 쪽에서 확인하지 못했다.

## 서비스의 두 갈래

| 갈래 | 중심 | 예 | 특징 |
| --- | --- | --- | --- |
| 캐릭터 중심 | 캐릭터 하나와의 1:1 대화 | zeta, Character.AI, BabeChat, 크랙의 캐릭터 | 시장이 가장 크고 만들기 쉽다 |
| 세계관 중심 | 세계 안의 여러 인물과 이야기 | 위프, 케이브덕의 에피소드, 프론티아, 젠잇, 러비더비의 씬 | 여러 인물을 만나다 한 명을 정하는 구조, 이벤트, 엔딩, 호감도 |

- 업계는 "캐릭터 하나만 만든다"에서 **세계관 > 캐릭터 > 시작 상황** 구조로 옮겨 가는 중이다.
- 정식으로 "여러 캐릭터가 한 방에서"는 약하다. 루나톡의 멀티버스는 끝났고, 크랙(파티챗), 에덴챗(다인 채팅), HYZE(그룹 채팅)가 시도 중이다.
- 이벤트맵과 엔딩(프론티아), 미션과 멀티 엔딩(위프), 관계 레벨(이루다)은 있다.

## 캐릭터를 만드는 구조

제작 화면은 다섯 층으로 정리된다.

| 층 | 내용 |
| --- | --- |
| 묶음 | 세계관 > 캐릭터 > 시작 상황(에피소드, 씬, 도입부 3~10개). 시작 상황마다 비밀 설정과 문체를 따로 두는 곳도 있다 |
| 글 | 메인 프롬프트(6천~1만 자가 표준), 소개와 썸네일과 태그, 예시 대화 5~10개, 시작 상황, 문체 가이드 |
| 로어북 | 키워드가 나오면 끼워 넣는 방식이 표준. 항목당 500자, 동시 5~10개. 고급형은 정규식, 턴 수, 주사위, 랜덤으로 발동 |
| 이미지 | 캐릭터마다 100장 안팎. 키워드나 감정에 따라 나오거나 호감도 단계에 따라 열린다. 장면 삽화 생성은 유료 부가 기능 |
| 상태와 로직 | 변수, 관계 점수와 단계, 작중 시간, 상태창, 노드, 블록코딩, 목표와 엔딩, 주사위 |

**공백.** 상태를 **누가 바꾸는지**는 어느 문서에도 분명하지 않다. 대부분 모델이 쓴 글에서 값을 읽거나, 모델에게 상태창을 쓰게 한다.
그래서 "상태창 오작동", "여러 인물이 한 명처럼 행동" 같은 불만이 반복된다. 상태를 서버가 검증해서 바꾸는 서비스는 보이지 않는다.
노드와 블록코딩으로 규칙을 짜게 하는 서비스는 강력하지만 제작 난도가 높다는 평이다.

## 사용자 쪽 설정

| 기능 | 흐름 |
| --- | --- |
| 페르소나(내 설정) | 표준. 여러 개를 둔다 |
| 유저노트 | 표준. 확장은 유료인 곳이 많다 |
| 장기기억 | 일정 턴마다 요약하거나 다단계로 둔다. **열람, 수정, 고정**이 되는 쪽으로 간다 |
| 다시 생성 | 지시문을 더하거나 모델을 바꿔 다시 받는다. 표준 |
| 수정, 분기, 채팅방 복사 | 2026년에 여러 서비스가 함께 추가했다 |
| 진행 보조 | 자동 답장, 이어서 진행, 추천 답변, 속마음 보기. 유료 부가 기능이 많다 |
| 출력량 | 1~5배. 종량 과금 |

## 돈을 받는 방식

- 재화 하나가 대략 1원이다. 웹 결제가 앱 결제보다 싸다.
- **모델마다 값이 다르다.** 가장 싼 것과 비싼 것의 차이가 10배 넘게 난다.
- 무료는 출석이나 하루 횟수로 주고, 기한이 지나면 사라진다.
- 1회 고정과 토큰 종량제를 함께 두는 곳이 늘었다. 원가에 수수료를 붙여 공개한 곳도 있다.
- 기간권, 구독, 부가 기능별 과금이 있다.
- **실패한 응답은 재화를 돌려준다.** 서비스 약속으로 내세우는 곳이 있다. 거부했는데 재화를 뗀 일은 비판받았다.
- 제작자 보상은 사용액의 한 자릿수 퍼센트가 흔하고, 현금보다 자사 재화로 주는 곳이 많다. 처우 불만이 반복된다.

## 반복되는 문제

1. 서버 장애와 그 보상
2. 예고 없는 가격 인상, 무료 재화 회수, 재화 단위 변경
3. 기억이 부실하거나 볼 수 없음
4. 상태창과 변수가 틀어짐, 여러 인물이 섞임
5. 검열로 거부했는데 재화를 뗌. 반대로 가드레일이 뚫림
6. 캐릭터와 그림의 도용
7. 결제 대행사 문제로 서비스 종료
8. 운영진의 소통 부족
9. 학습 데이터의 개인정보 노출

## 이 저장소에 주는 것

**이미 있는 것과 맞물린다.**

| 다른 서비스의 것 | 이 저장소에 있는 것 |
| --- | --- |
| 세계관 > 캐릭터 > 시작 상황 | 세계관 자산, 시나리오의 스타팅 |
| 키워드 로어북 | 로어북(키워드와 벡터 검색) |
| 요약형 장기기억 | 기억 색인 |
| 페르소나 | 페르소나 보관함 |
| 모델별 값 | 모델마다의 가격표, 모델 목록, 시나리오의 추천 모델 |
| 매일 무료, 출석 | 기한이 있는 무료 크레딧, 출석 |
| 실패한 응답 환불 | 홀드 → 성공하면 확정, 실패하면 반환 |
| 주사위와 상태창 | 엔진의 판정과 상태 |
| 성인 확인 | 본인인증, 보호자 동의 |

**차별점이 될 수 있는 것.**

1. 상태는 서버가 바꾼다. 제작자가 변수(이름, 타입, 범위, 모델이 바꿀 수 있는지, 한 턴에 바뀌는 한도)를 정의하고, 모델은 바꿀 제안을 구조화해서 내고, 서버가 검증해 DB 에 반영한다.
2. 변수 갱신 규칙은 노드나 블록코딩이 아니라 표로 채우는 선언형으로 한다(칸 정의, 범위, 증감 한도, 단계별 해금).
3. 기억을 보여 주고 고치게 한다.
4. 실패하면 저절로 돌려준다.
5. 여러 사람이 함께. 대부분 1:1 이고 다인은 시도 단계다.

**새로 필요한 것.** 캐릭터 만들기와 탐색, 다시 생성·수정·분기, 호감도와 해금, 선톡(먼저 말 걸기), 제작자 보상, 신고와 검수. 이들은 TRPG 를 만든다고 따라오지 않는다.
