# 시나리오 업적 설계

제작자가 자기 작품에 다는 업적이다. 스팀의 업적과 같다. 이 문서는 TRPG 의 것이다. story 와 chat 은 그 서버가 따로 갖는다.
인증 서버의 활동 배지(출석, 본인인증, 초대 같은 일반 도전과제, #193)와는 완전히 다른 것이다. 섞지 않는다.

- 정한 날: 2026-11-08(유저 결정)
- 관련: 퀘스트의 조건(`trpg-server/README.md` 의 "퀘스트"), [장](chapters.md), 인증 서버의 활동 배지(`auth-server/README.md` 의 "활동 배지")

## 정한 것

| 무엇 | 정한 것 | 까닭 |
| --- | --- | --- |
| 누가 다나 | 제작자가 시나리오마다 단다 | 작품마다 그 작품의 이야기에 맞는 업적이 있다. 서비스가 정하는 일반 도전과제는 인증 서버의 배지다 |
| 누가 주나 | 엔진뿐이다. 방장도 AI(서술, 장부 초안)도 주지 못한다 | 게임의 결과는 엔진이 정한다. AI 의 말이 기록을 바꾸지 못한다 |
| 누구에게 남나 | 계정마다, 시나리오마다 한 번 | 스팀처럼 여러 판을 돌아도 한 번이다. 캐릭터에 남기면 캐릭터를 지울 때 사라진다 |
| 판 안의 누가 받나 | 조건을 채운 테이블에 그때 캐릭터를 갖고 앉아 있는 사람 모두 | 협동 게임의 업적과 같다. 조건마다 누가 했는지를 가리면 퀘스트의 조건과 모양이 달라진다 |
| 숨긴 업적 | 둔다. 받기 전에는 이름, 설명, 그림을 가린다 | 이야기의 반전이 업적 이름으로 새지 않게 한다 |
| 달성률 | 보인다. 업적마다 받은 사람의 수와 플레이한 사람의 수 | 플레이한 사람이 어려운 업적을 알아본다 |
| 그림 | 제작자가 올린 그림을 단다(`/portraits`) | 프리젠의 그림, 로어 항목의 그림과 같은 길이다 |
| 보상 | 없다 | 업적은 기록이다. 보상은 퀘스트의 것이다 |

## 모양

시나리오의 `achievements` 다. 판에도 그대로 굳힌다. 비워도 되는 칸이라 판의 형식이 그대로다(없던 판은 업적이 없다).

```json
{
  "id": "dragon-awake",
  "name": "용을 깨운 자",
  "description": "잠든 용을 깨웠다",
  "hidden": true,
  "image_id": "…",
  "when": [{ "kind": "quest_succeeded", "target": "…" }],
  "match": "all"
}
```

| 칸 | 뜻 |
| --- | --- |
| `id` | 판이 바뀌어도 그대로 두는 이름표(1~40자). 받은 기록이 이것을 가리킨다. 바꾸면 다른 업적이다 |
| `name`, `description` | 이름(1~40자)과 받는 법(200자까지). 받는 법은 숨기지 않은 업적이면 받기 전에도 보인다 |
| `hidden` | 받기 전에는 이름, 설명, 그림을 가린다 |
| `image_id` | 제작자가 올린 그림. 남의 그림이나 없는 그림은 저장할 때 422 `achievements.image_id` |
| `when`, `match` | 받는 조건. 퀘스트의 조건과 같은 모양과 종류다. 하나 이상이고, 가져가기(`consume`)는 쓰지 않는다 |

한 시나리오에 50개까지다. 같은 `id` 가 두 번이면 422 다.

## 받는 규칙

라운드가 닫힐 때 엔진이 본다. 퀘스트, 사건, 장, 기한을 모두 본 뒤다. 같은 라운드에 이룬 퀘스트와 넘어간 장을 조건이 본다.

- 받는 사람은 그때 캐릭터를 갖고 앉아 있는 사람 모두다. 쓰러지거나 죽은 캐릭터의 사람도 받는다
- 테이블마다 한 번 본다. 받은 것은 테이블에 적어 다시 주지 않는다
- 계정의 기록은 한 번이다. 다른 테이블에서 또 받아도 처음 받은 때와 테이블이 남는다
- 받으면 테이블의 모두에게 이벤트로 알린다. 조건은 싣지 않는다
- 라운드를 되돌리면 테이블의 기록은 되돌아간다. 계정에 남은 업적은 되돌리지 않는다

## 게시할 때 보는 것

조건은 퀘스트의 조건과 같이 본다. 가리키는 것이 붙인 로어북에 있는지, 종류가 맞는지, 이룰 수 있는지다.

| 문제 | 뜻 |
| --- | --- |
| `achievement_condition_missing` | 조건이 가리키는 것이 없다 |
| `achievement_condition_invalid` | 조건이 맞지 않는 종류를 가리킨다 |
| `achievement_condition_impossible` | 조건을 채울 수 없다(맵에 없는 장소, 놓인 마리보다 많이 …). 아무도 받지 못한다 |

## 공개

`GET /api/v1/game/listings/{scenario_id}/achievements` 는 공개된 시나리오의 업적을 판의 차례로 준다. 로그인하지 않아도 본다(#530).

- 업적마다 받은 사람의 수(`earned_count`), 전체에 플레이한 사람의 수(`players`)다. 달성률은 화면이 나눈다
- 로그인했으면 내가 받은 때(`earned_at`)가 있고, 받은 숨긴 업적은 이름과 그림이 보인다
- 볼 수 없는 시나리오(공개하지 않음, 볼 수 없는 등급)는 404 다. 공개 정보의 규칙과 같다
- 그림의 바이트는 공개된 시나리오의 그림 주소(`/listings/{id}/portraits/{id}/image`)와 테이블의 그림 주소로 받는다. 업적에 붙은 그림은 지우지 못한다(409)

## 기록

| 표 | 무엇 |
| --- | --- |
| `player_achievements` | 누가 어느 시나리오의 어느 업적을 언제, 어느 테이블에서 받았나. 기본 키는 (사람, 시나리오, 업적) |
| `scenario_players` | 누가 그 시나리오를 플레이했나. 캐릭터를 갖고 앉은 테이블에서 라운드가 한 번이라도 닫힌 사람이다. 달성률의 분모다 |

- 업적의 정의는 시나리오와 판에 있다. 기록에는 `id` 만 적는다. 판에서 업적을 빼도 받은 기록은 남는다(목록에는 보이지 않는다)
- 탈퇴하면 그 사람의 업적과 플레이의 기록을 지운다. 달성률에서 빠진다
- 이 기능 전의 플레이는 세지 않는다. 이제부터 센다

## 만드는 순서

1. 업적을 적고 게시하기, 기록의 표, 공개 목록, 탈퇴
2. 라운드가 닫힐 때 엔진이 주기. 테이블의 기록, 이벤트, 되돌리기, 플레이한 사람 세기
3. 화면: 제작 도구의 업적 편집, 시나리오 소개의 업적과 달성률, 테이블 방의 "업적을 얻었다"
