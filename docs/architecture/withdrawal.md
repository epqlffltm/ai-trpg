# 탈퇴

회원이 스스로 계정을 지우는 길이다. 개인정보 처리방침의 "삭제 요구"와 이용약관의 "동의하지 않으면 탈퇴"가 이 길에 걸려 있다([개인정보 처리방침 초안](../legal/privacy.md)의 검토할 것 3).
2026-10-21 에 정했다(#603). 구현하는 PR 이 아래 [만드는 순서](#만드는-순서)의 칸을 고친다. 인증 서버의 것은 [인증 서버 README 의 탈퇴](../../auth-server/README.md#탈퇴)에 있다.

탈퇴는 모든 서버의 데이터에 걸친다. 이 문서는 서버마다 무엇을 지우고 무엇을 남기는지, 인증 서버가 다른 서버에 어떻게 알리는지를 한곳에 정한다. 받는 쪽의 자세한 구현은 그 서버의 README 에 적고 여기서는 가리키기만 한다.

## 정한 것 (유저 결정, 2026-10-21)

| 질문 | 결정 | 고르지 않은 것과 까닭 |
| --- | --- | --- |
| 바로 지우는가 | **7일 유예.** 누르면 바로 막고 7일 뒤에 지운다. 그 안에 다시 로그인해 취소한다 | 바로 지우기: 단순하지만 되돌릴 수 없다. 도용된 계정이나 실수로 누른 것을 살릴 길이 없다 |
| 남은 골드 | **알리고 소멸.** 탈퇴 화면에 남은 골드와 "사라진다"를 보이고 확인을 받는다. 7일 안의 쓰지 않은 주문은 먼저 청약철회하라고 안내한다 | 골드가 있으면 막기: 돈이 사라지는 일은 없지만 삭제 요구를 막는 셈이다. 잔액 환불을 둘지는 변호사의 답을 보고 다시 정한다 |
| 요청을 메일의 링크로 한 번 더 확인하는가 | **하지 않는다**(2026-10-22, #624). 비밀번호, 7일 유예, 알림 메일, 로그인으로 취소가 이미 막는다 | 확인 링크: 메일이 오지 않으면 나가지 못해 삭제 요구가 막힌다. "링크를 눌러 확인하라"는 메일에 익숙해지면 가짜 메일에도 누른다. 메일을 빼앗긴 경우에는 막지 못한다 |
| 다시 알리는가 | **마치기 하루 전에 한 번**(2026-10-22, #624). 요청마다 한 통이다. 워커가 늦어도 마치는 시각은 늦추지 않는다 | 매일: 메일이 많아 스팸으로 간다 |
| 정지된 계정 | **지금대로 둔다**(2026-10-22). 정지된 계정은 로그인하지 못하므로 탈퇴를 요청하지 못한다. 유예 중에 정지되어도 탈퇴는 그대로 마친다. 정지된 사람이 탈퇴하고 다시 가입해 정지를 피하는 것은 따로 막는다(본인인증의 구별 값, #634) | 정지되면 탈퇴를 멈추기: 운영자가 풀 때까지 개인정보를 쥐고 있게 되고, 멈춘 탈퇴를 다시 돌릴 길을 따로 만들어야 한다. 정지 중에도 요청 받기: 정지된 계정에 로그인의 길을 하나 열게 된다 |
| 유예 동안 미성년자의 보호자에게 알리는가 | **알리지 않는다**(2026-10-22). 만 14세 이상은 본인이 동의하므로 탈퇴도 본인의 일이다. 보호자에게는 결제와 청약철회만 알린다(#352) | 남은 골드가 있을 때만 알리기, 늘 알리기: 보호자의 이메일을 탈퇴의 길에서도 써야 한다. 동의한 보호자가 없는 미성년자와 갈린다 |
| 다른 서버에 알리는 길 | **인증 서버의 발송함에서 민다.** 서버마다 한 줄을 적고, 서명해 보내고, 2xx 를 받을 때까지 다시 보낸다 | 목록을 내고 끌어가기(끊긴 세션의 목록처럼): 받는 쪽마다 어디까지 했는지 기억해야 하고 목록이 끝없이 커진다 |

## 흐름

```
요청(POST /me/withdrawal, 비밀번호)
  ├ 계정에 요청 시각을 적는다. 모든 세션을 끊는다(세션 버전을 올린다)
  ├ "탈퇴를 받았다. 7일 뒤 지운다. 취소하려면 로그인한다" 메일
  │
  │  7일(유예)
  │   ├ 로그인은 된다. 토큰은 인증 서버에만 통한다(아래 "유예 동안")
  │   ├ 취소(DELETE /me/withdrawal) → 요청 시각을 지운다. /refresh 로 모든 서버에 통하는 토큰
  │   └ 마치기 하루 전(6일째): "○월 ○일 ○시에 지운다. 취소하려면 로그인한다" 메일 한 통(#624)
  │
  └ 7일이 지나면 정리 작업이 마친다
      ├ 인증 서버의 개인정보를 지운다(아래 표)
      ├ 서버마다 알릴 줄을 적는다(같은 트랜잭션)
      └ 발송함의 워커가 서버마다 보낸다. 2xx 까지 다시 보낸다
```

- **요청에 비밀번호를 받는다.** 열린 채 둔 기기에서 남이 누르지 못하게 한다. 로그인할 때 이메일 코드를 이미 받았으므로 코드는 다시 받지 않는다
- **요청하면 세션을 모두 끊는다.** 다른 기기에서 쓰던 토큰도 15분 안에 끊긴다(끊긴 세션의 목록, 30초쯤)
- **하루 전 알림은 요청마다 한 통이다.** 계정에 보낸 시각(`withdrawal_reminded_at`)을 적고 요청할 때 비운다. 취소하고 다시 요청하면 새 요청에 한 통을 더 보낸다. 보낸 시각과 메일(발송함의 줄)은 한 트랜잭션이고, 워커 둘이 같은 계정을 골라도 줄을 잠근 뒤 다시 본다
- **워커가 늦어도 마치는 시각은 그대로다.** 하루 전이 지나 떴으면 마치기 전에만 보낸다. 마칠 때가 지났으면 보내지 않고 같은 바퀴에 마친다. 메일에는 "내일"이 아니라 지우는 시각을 적는다. 메일 서버가 멈춰 발송함에 남은 알림은 마칠 때 그 주소로 보낼 다른 메일과 함께 지운다(마친 뒤에 "곧 지운다"가 가지 않는다)
- 완료는 요청 시각에서 7일이다. 결제 서버에 맡기는 워커(`send_welcome_credits`)가 바퀴마다 때가 된 계정을 마친다. 마치는 일은 몇 번 돌려도 같은 결과다(줄을 잠근 뒤 다시 본다)
- 요청의 비밀번호는 비밀번호 변경과 같은 시도 한도를 센다
- 탈퇴한 이메일로 다시 가입할 수 있다. 새 계정이다. 같은 사람이 환영 크레딧을 다시 받지는 못한다(아래 "남기는 것")

## 유예 동안

다시 동의할 것이 남은 사람과 같은 방법을 쓴다(`auth-server/accounts/tokens.py` 의 `audience_for`, #586).

- 로그인과 `/refresh` 는 된다. 토큰의 대상(`aud`)이 인증 서버뿐이라 다른 서버는 `401` 이다
- 토큰을 주는 응답과 `/me` 에 계정을 비울 시각(`withdrawal_scheduled_at`)이 실린다. 화면은 이것을 보고 "7일 뒤 지워진다. 취소할까" 화면만 연다
- 인증 서버의 주소는 그대로 쓴다. 취소, 내 정보, 로그아웃 등
- 다른 서버를 고치지 않는다. 유예 동안 다른 서버의 데이터는 그대로다. 게임의 테이블에 앉아 있었다면 그 자리는 그대로 있고 서술의 값이 모자라 빠질 수 있다

## 마칠 때: 인증 서버

계정의 줄은 지우지 않고 비운다. 만 14세 미만 계정을 닫는 일(`accounts/identity.py` 의 `close_under_age_account`)과 같은 방법이다.
줄을 지우면 세션 버전이 사라져 다른 서버가 끊긴 세션을 알 길이 없고, 공개 ID 가 사라져 다른 서버가 그 사람의 것을 가려 지울 수 없다.

| 무엇 | 처리 |
| --- | --- |
| 아이디, 닉네임, 이메일, 비밀번호 | 지운다(`removed-<번호>` 로 바꾼다). 계정을 막는다 |
| 이메일 코드, 가입 코드, 보낼 메일 | 지운다 |
| 동의 기록 | 지운다 |
| 정지의 기록(사유의 종류, 운영자가 적은 사유) | 지운다. 정지된 채 탈퇴하면 재가입을 막는 값(본인인증과 이메일을 서명한 것)을 사유의 기간만큼 따로 남긴다(#634, 인증 서버 README 의 "재가입 막기") |
| 본인인증의 기록(사람의 구별 값, 미성년자의 날짜) | 지운다 |
| 보호자 동의(보호자의 이메일, 구별 값) | 지운다 |
| 결제 자격 | 지운다(결제 서버의 것은 결제 서버가 지운다) |
| 보호자 결제 알림의 기록 | 〔정할 것: 결제의 법정 보존과 함께 정한다(처리방침 초안의 검토할 것 5, 6)〕 |
| 공개 ID | 남긴다. 다른 서버가 그 사람의 것을 찾는 열쇠다. 사람을 알아볼 수 있는 값이 아니다 |
| 환영 크레딧을 받은 사람의 구별 값 | 남긴다. 같은 사람이 계정을 바꿔 다시 받지 못하게 한다. 처리방침에 적는다 |
| 보안 기록(IP) | 남긴다. 30일이 지나면 함께 지워진다 |

## 마칠 때: 다른 서버

인증 서버가 알리면 그 서버가 자기 데이터를 정리한다. 다른 서버의 DB 를 고치지 않는다.

| 서버 | 하는 일 | 상태 |
| --- | --- | --- |
| 결제 | 걸린 홀드를 돌려주고(`withdrawn`) 골드와 실버를 소멸로 적는다(원장의 이유 `forfeit`). 둘은 지갑을 잠근 한 트랜잭션이다. 결제 자격을 지운다. 보내지 않은 사용자의 알림은 멈춘다(지우면 정리 작업이 다시 적는다. 30일 뒤 지워진다). 결과를 모르는 주문(`confirming`, `refunding`)은 대사가 그대로 끝낸다. 원장, 주문, 홀드, 출석, 보호자 결제 알림의 기록은 남긴다(공개 ID 만 있다) | 만들었다(`billing-server/README.md` 의 탈퇴) |
| 알림 | 알림함(읽은 것 모두)과 끈 알림의 종류를 지운다. 남기는 것이 없다 | 받는 주소를 만들었다(`notification-server/README.md` 의 "탈퇴 받기") |
| 게임 | 모집 중, 진행 중인 테이블에서 나간다(스스로 나가기와 같다. 방장이면 넘기고, 혼자면 끝낸다). 끝난 테이블의 자리는 남긴다. 보관함(페르소나)을 지운다. 시나리오의 공개를 내린다. 자산과 판은 지우지 않고 남기고, 진행 중인 테이블은 판의 사본으로 돈다. 보내지 않은 알림을 지운다. 테이블의 기록(대화, 선언, 귓속말)은 남기고 이름을 "탈퇴한 사용자"로 보인다 | 정했다(2026-10-21 유저 결정). 받는 주소를 만들었다(`trpg-server/README.md` 의 "탈퇴") |
| 게시판 | 글과 댓글(지운 것도)은 남기고 `author_id` 를 비워 "탈퇴한 사용자"로 보인다(`author_withdrawn`). 신고는 남기고 신고한 사람을 비운다. 닉네임과 보낼 알림을 지운다 | 받는 주소를 만들었다(`board-server/README.md` 의 "탈퇴 받기") |
| asset | 페르소나, 비공개 캐릭터, 그림, 아직 보내지 않은 알림(#678)을 지운다. 공개 캐릭터와 그 판, 그 판에 쓰인 그림은 남긴다 | 받는 주소를 만들었다(`asset-server/README.md` 의 "탈퇴"). 그림도 지운다(#566. 저장소에서 먼저 지우고 행은 나중이다. 저장소에 닿지 못하면 503 이라 다시 보낸 알림이 마저 지운다) |
| chat | 대화(지운 것으로 적어 둔 것까지)와 딸린 것(말, 상태, 요약, 기억 메모, 페르소나의 사본), 가져온 캐릭터의 판의 사본, 연 이벤트 씬의 기록을 지운다. 청구 기록(`generations`)은 남기고 대화와 말을 가리키는 칸만 비운다(공개 ID, 모델, 토큰 수, 원가, 청구 상태, 홀드의 이름표가 남는다. 2026-10-23 유저 결정) | 받는 주소를 만들었다(`chat-server/README.md` 의 "탈퇴", #670) |
| story | 대화를 지운다 | 제안. 서버를 만들 때 정한다 |

- 남긴 기록에서 사람을 알아볼 수 있는 것은 공개 ID 뿐이다. 인증 서버가 그 ID 의 이름을 지웠으므로 이름을 물으면 `null` 이다(`/public-names`). 화면은 "탈퇴한 사용자"로 보인다

## 알리는 길

```
POST /api/v1/<서버>/service/users/{public_id}/withdrawal
본문: {"withdrawn_at": "2026-10-28T03:00:00Z"}
서명: 서버끼리의 서명(server_core 의 service_auth, 결제는 serviceauth). 비밀은 받는 서버마다 따로
```

- **인증 서버의 발송함.** 마칠 때 같은 트랜잭션에서 아래 표의 모든 서버에 한 줄씩 적는다. 워커가 보내고, `200` `processed` 면 끝, 아니면 5초에서 1시간까지 늘려 다시 보낸다. 환영 크레딧과 결제 자격을 맡기는 길과 같은 모양이다
- **보내는 워커는 `send_welcome_credits` 다**(compose 의 `auth-welcome-credits`). 새 프로세스를 두지 않는다. 그래서 받는 서버의 비밀(아래 표의 인증 쪽 이름)은 이 프로세스에 준다
- **받는 쪽은 멱등이다.** 같은 알림이 두 번 와도 결과가 같다. 이미 정리했으면 `200` 이다. 모르는 사용자(그 서버에 데이터가 없다)도 `200` 이다. 본문은 `{"status": "processed"}` 다. 그 밖의 답(옛 판이라 `404` 인 것 포함)은 다시 보낸다
- **비밀이 비어 있는 서버에는 보내지 않는다.** 줄은 적어 두고 기다린다. 받는 주소를 만들고 비밀을 적으면 그 전에 탈퇴한 사람의 것도 나간다.
  그래서 받는 쪽의 PR 은 인증 서버의 코드를 고치지 않는다. `.env.example` 에 비밀 한 줄을 더할 뿐이다(인증 서버는 칸을 미리 열어 두었다)
- 아직 없는 서버(story)는 표에 없다. 받는 주소를 만들 때 인증 서버의 표(`accounts/withdrawal_client.py` 의 `DESTINATIONS`, `WithdrawalTarget`)에 더한다. 그 전에 탈퇴한 사람의 데이터는 그 서버에 없다

**서버마다의 이름(인프라와 정함, 2026-10-21).** 비밀은 받는 서버마다 따로다. 인증 쪽의 이름은 `<서버>_SECRET`, 받는 쪽은 모두 `AUTH_SERVER_SECRET` 이다(인증 ↔ 결제의 짝과 같은 모양).

| 받는 서버 | 주소의 머리 | 인증 쪽의 주소 / 비밀 | 받는 쪽의 비밀 | 인증 쪽 상태 |
| --- | --- | --- | --- | --- |
| 결제 | `/api/v1/billing` | `BILLING_URL`(8003) / `BILLING_SECRET` | `AUTH_SERVER_SECRET` | 이미 있다 |
| 알림 | `/api/v1/notification` | `NOTIFICATION_URL`(8004) / `NOTIFICATION_SECRET` | `AUTH_SERVER_SECRET` | 받는 주소와 비밀을 만들었다 |
| 게임 | `/api/v1/game` | `GAME_URL`(8001) / `GAME_SECRET` | `AUTH_SERVER_SECRET` | 받는 주소와 비밀을 만들었다 |
| 게시판 | `/api/v1/board` | `BOARD_URL`(8002) / `BOARD_SECRET` | `AUTH_SERVER_SECRET` | 받는 주소와 비밀을 만들었다 |
| asset | `/api/v1/asset` | `ASSET_URL`(8006) / `ASSET_SECRET` | `AUTH_SERVER_SECRET` | 받는 주소와 비밀을 만들었다 |
| chat | `/api/v1/chat` | `CHAT_URL`(8005) / `CHAT_SECRET` | `AUTH_SERVER_SECRET` | 받는 주소와 비밀을 만들었다(#670). 인증 서버의 표(`WithdrawalTarget`, `DESTINATIONS`)에도 더했다 |

- 주소의 기본값은 로컬의 포트다(`http://127.0.0.1:<포트>`). compose 에서는 그 서버의 컨테이너 이름으로 적는다
- 받는 주소를 만드는 PR 이 함께 고치는 것: 두 서버의 `.env.example`, `secret_scope.py` 의 표, `fill_env.py` 의 짝과 그 시험, compose 에서 비우는 줄과 `auth-welcome-credits` 의 주소. 어려우면 인프라 쪽이 그 브랜치에 얹을 zip 을 준다
- 알리지 못할 때마다 로그에 `warning`(`withdrawal.undelivered`)이 남고, 인증 서버의 관리자 화면 "탈퇴 알림"에 시도 횟수와 마지막 오류가 남는다.
- **경보**(`docker/prometheus/rules/ai-trpg.yml`): 비밀을 적은 서버에 알리지 못한 줄이 2시간 동안 남으면 `AuthWithdrawalNoticesWaiting`, 비울 시각이 지난 계정이 30분 동안 남으면 `AuthWithdrawalsOverdue`, 워커가 10분 동안 돌지 않으면 `AuthWelcomeCreditsWorkerStalled` 다. 워커가 바퀴마다 두 수를 `background_jobs_queued` 로 적는다

## 열린 질문

- 법적 요청에 대비해 탈퇴한 사람의 기록을 얼마 동안 따로 두는가(처리방침의 법정 보존과 함께)
- 다른 사람이 플레이 중인 공개 시나리오를 내리면 그 테이블은 어떻게 되는가(지금의 제재와 같이 이미 열린 테이블은 그대로 두는 안)
- 탈퇴 전에 자기 기록(대화, 시나리오)을 내려받는 길
- 이메일 바꾸기를 만들 때: 옛 주소에도 알린다. 빼앗긴 계정이 이메일부터 바꾸고 탈퇴하면 위의 메일이 모두 새 주소로 간다. 유예 중에 이메일을 바꾸지 못하게 할지도 그때 정한다(#624 의 "지킬 것")
