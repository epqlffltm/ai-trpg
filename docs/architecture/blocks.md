# 차단

보기 싫은 제작자와 태그를 막는다(#988). 막은 제작자의 작품과 막은 태그가 붙은 작품은 목록에서 빠진다.

## 정한 것(2026-11-04 유저 결정)

- **막은 목록은 인증 서버에 둔다.** 여러 서비스(TRPG, chat, story)의 화면이 함께 읽고, 기기를 바꿔도 같아야 한다. 성인 작품 숨김(#986)과 같은 자리다
- **목록을 내는 서버는 인증 서버를 부르지 않는다**([공용 코드 규칙의 원칙 2](shared-code.md#원칙)). 화면이 막은 목록을 읽어 목록의 주소에 싣는다
- **상한은 제작자 100명, 태그 30개다.** 주소에 싣기 때문이다(아래)
- **빼는 곳:** 공개 목록, 검색, 랭킹, 배너. 소개 하나를 여는 주소에는 싣지 않는다(링크로 받은 작품은 열린다). 이미 연 대화와 테이블에도 미치지 않는다
- **이번에는 제작자와 태그만이다.** 사용자 차단(게시판의 글·댓글, TRPG 테이블)은 범위를 따로 정해 다음에 한다

## 만드는 차례

1. 목록을 내는 서버(trpg-server, asset-server)가 뺄 값을 받는다 — 이 문서의 "주소" (먼저 한다. 화면이 싣기 전에 서버가 받아야 한다)
2. 인증 서버가 막은 목록을 갖고(`/me` 의 API), 화면이 차단 관리와 "차단하기"를 두고 목록의 주소에 싣는다

## 주소

```
GET /api/v1/game/listings?exclude_creators=<공개 ID>,<공개 ID>&exclude_tag=<태그>&exclude_tag=<태그>
```

| 칸 | 모양 | 상한 |
| --- | --- | --- |
| `exclude_creators` | 제작자의 공개 ID 를 쉼표로 잇는다. 앞뒤 공백과 빈 조각은 버리고 겹친 것은 하나로 본다 | 100명 |
| `exclude_tag` | 태그 하나. 이름을 되풀이한다(태그에는 쉼표가 들어갈 수 있다). 앞뒤 공백을 떼고 1~20자 | 30개 |

- 받는 주소: `/api/v1/game/listings`, `/api/v1/game/rankings/scenarios`, `/api/v1/game/banners`,
  `/api/v1/asset/listings/characters`, `/api/v1/asset/listings/worlds`, `/api/v1/asset/rankings/{characters,worlds}`, `/api/v1/asset/banners`
- 막은 제작자의 것과, 막은 태그가 하나라도 붙은 것을 뺀다. 태그는 대소문자를 가린다(작품의 태그와 똑같은 것)
  - 시나리오: 공개 정보의 태그(`listings.tags`)
  - 캐릭터와 세계관: 마지막 판의 태그(`document.tags`)
- 넘거나 공개 ID 가 아니면 422 다. 화면의 잘못이다
- 코드: trpg-server 의 `app/listings/exclusions.py`, asset-server 의 `app/exclusions.py`

### 주소의 길이

한글은 주소에서 한 글자가 9바이트다(UTF-8 3바이트를 %XX 로 쓴다). 가장 길면

- 제작자 100명: 36자와 쉼표 × 100 ≈ 3.7KB
- 태그 30개: (`exclude_tag=` 12바이트 + 20자 × 9바이트) × 30 ≈ 5.8KB

라서 주소가 9.5KB 쯤이 된다. nginx 의 기본 상한(요청의 줄 8KB)을 넘으므로 프록시의 `large_client_header_buffers` 를 16KB 로 둔다
(`docker/nginx/templates/http.inc.template`). 서버(uvicorn)는 요청의 줄과 머리말을 합쳐 16KB 까지 받는다.
태그를 50개로 두면 15KB 를 넘어 머리말(토큰)과 함께 서버의 상한에 걸릴 수 있어 30개로 정했다.

다른 길도 있었다.

| 길 | 버린 까닭 |
| --- | --- |
| 목록을 내는 서버가 막은 목록의 사본을 받아 둔다(인증 서버가 바뀔 때마다 보낸다) | 주소의 문제는 없지만 표, 발송, 서버끼리의 API 가 서버마다 는다 |
| 화면이 받은 뒤에 거른다 | 한 쪽에 20개보다 적게 보이고, 개수(`total`)와 랭킹의 순위가 맞지 않는다 |
