# asset 서버 설계

제작자가 만드는 것과 사용자가 자기 것으로 만드는 것의 원본을 맡는 `asset-server` 를 만들기 전에, 무엇을 맡고 어떻게 내주는지를 적는다. 서버는 아직 없다. 모두 계획이다.

- 기준: `main` `0172264` (2026-10-21)
- 서비스 사이의 원칙(자산은 시작할 때 판을 복사해 고정한다, 턴마다 부르지 않는다)은 [서비스 구조 명세](services.md)와 [공용 코드 규칙](shared-code.md)에 있다. 여기에는 asset-server 안의 일을 적는다.
- 그림을 두는 곳은 [배포 설계의 그림 저장소](deployment.md#그림-저장소)에 정했다.

## 정한 것

| 항목 | 정한 것 | 까닭 |
| --- | --- | --- |
| 계정 페르소나의 집 | asset-server(2026-10-21) | 제작한 것을 "시작할 때 복사해 고정"하는 규칙과 그림 저장소를 그대로 쓴다. 인증 서버에 놀이의 데이터를 섞지 않는다 |
| TRPG 의 능력치 | 계정 페르소나는 공통 칸만 갖는다. TRPG 의 보관함은 "계정 페르소나를 가리키는 TRPG 의 시트(능력치, 룰북)"가 되고, 테이블로 가져갈 때 둘을 합쳐 사본을 뜬다(2026-10-21) | asset-server 가 TRPG 의 규칙을 몰라도 된다(공용 코드의 원칙 5). 지금의 보관함과 테이블 코드가 거의 그대로다 |
| 세션이 쓰는 방식 | 세션을 시작할 때(또는 대화 안에서 바꿀 때) 복사해 고정한다. 페르소나를 고친 뒤에는 대화 안에 "새 설정으로 바꾸기"를 보인다(2026-10-21) | 턴마다 asset-server 를 부르지 않는다. 바꾸는 것은 사용자가 고른다 |
| 페르소나의 칸 | 이름, 설명, 프로필 그림, 나이, 성별, 호칭, 말투 예시, 성격(2026-10-21) | 모델이 사용자를 부르는 말이 맞고, 다른 서비스만큼 꾸밀 수 있다 |
| 나이와 성별 | 어느 것으로도 거르거나 막지 않는다. 나이 칸은 고르는 칸이다(2026-10-21) | [chat 서버 설계의 성인 콘텐츠](chat-server.md#성인-콘텐츠) |
| 만드는 세션 | 새 세션(asset)을 연다. 인프라와 설계 문서를 맡는 세션이 그림 저장소, compose, CI 를 받쳐 준다(2026-10-21) | 서버마다 세션 하나라는 지금의 나눔과 맞다 |
| 언어와 틀 | FastAPI | chat-server 와 같고 `shared/`(소개 HTML 거르기, 템플릿)를 그대로 쓴다. TRPG 의 `app/assets` 를 옮겨 올 수 있다 |
| 첫 버전 | 계정 페르소나, 캐릭터, 그림 올리기와 내주기, 게시와 판 | chat 의 첫 버전에 필요한 것만이다. story 의 세계관과 TRPG 의 세계관·로어북은 다음 조각이다 |
| 자리 | 폴더 `asset-server/`, 포트 8006, 토큰의 대상 `ai-trpg-asset`, 스키마 `asset`, 초기화 스크립트 `08-asset-role.sql`, 주소 `/api/v1/asset/` | [서비스 구조 명세](services.md#계획인-것)의 예약 그대로. 만드는 PR 에서 확정한다 |

50~52번(만드는 세션, 언어, 첫 버전)은 2026-10-21 에 권한 안으로 적었다. 바뀌면 이 표를 고친다.

## 맡는 것

| 것 | 주인 | 공개 | 쓰는 곳 | 언제 |
| --- | --- | --- | --- | --- |
| 계정 페르소나 | 사용자 | 주인만 | TRPG, chat, story | 첫 버전 |
| 캐릭터 | 제작자 | 비공개 / 공개 | chat, story | 첫 버전 |
| 그림 | 올린 사람 | 그림이 붙은 것을 따른다 | 셋 모두 | 첫 버전 |
| story 의 세계관(인물, 장소, 이벤트, 엔딩) | 제작자 | 비공개 / 공개 | story | 다음 조각 |
| 세계관, 로어북과 항목 | 제작자 | 비공개 / 공개 | TRPG, chat, story | trpg-server 에서 옮긴다([순서](services.md#순서) 9) |

- asset-server 는 정의만 갖는다. 대화와 게임의 상태, 크레딧은 갖지 않는다.
- 판단하는 것은 "누가 이것을 볼 수 있고 쓸 수 있는가"(소유자, 공개 범위, 등급)뿐이다.

## 계정 페르소나

- 한 사람이 여러 개를 갖는다(TRPG 의 보관함처럼 상한을 둔다. 기본 50). 하나를 기본으로 둔다.
- 칸: 이름, 설명, 프로필 그림, 나이, 성별, 호칭(모델이 나를 부르는 말), 말투 예시, 성격. 이름 말고는 비워도 된다.
- 판이 없다. 주인만 쓰고, 세션이 가져갈 때 사본을 뜬다. 고칠 때마다 `revision`(숫자)이 오른다. 세션은 가져간 `revision` 을 적어 두고, 지금 것과 다르면 "새 설정으로 바꾸기"를 보인다.
- 지우면 행을 지운다. 가져간 세션은 사본을 갖고 있어 그대로 돈다(지금의 TRPG 보관함과 같다).
- **TRPG 의 보관함과 나누기.** 지금의 `trpg-server` 의 `personas`(이름, 설명, 능력치, 룰북)는 이렇게 된다.
  - 이름과 설명은 계정 페르소나로 옮긴다.
  - TRPG 에 남는 것은 시트(`persona_sheets`: 계정 페르소나의 id, 능력치, 룰북 이름)다.
  - 테이블로 가져갈 때 trpg-server 가 계정 페르소나의 사본과 시트를 합쳐 지금처럼 사본을 뜨고, 그 테이블의 규칙으로 검사한다.
  - 옮기는 일은 한 번의 이관이다. asset-server 가 생긴 뒤 trpg-server 의 관리 명령이 지금의 행을 계정 페르소나로 올리고 시트를 남긴다. 따로 설계한다.

## 게시와 판

TRPG 의 시나리오와 같은 방식이다.

- 제작자는 초안을 고치고, **게시**하면 판(번호가 오르는 고정된 사본)이 생긴다. 판은 바뀌지 않는다.
- 쓰는 서비스는 시작할 때 게시된 판 하나를 가져가 고정한다. 새 판이 나오면 알리기만 한다.
- 게시할 때 검사한다. 막히면 `problems[]` 로 돌려준다(TRPG 의 게시와 같은 모양).
  - 필수 칸, 그림이 있는지, 조건이 가리키는 장소와 물건이 있는지.
  - 소개 글의 HTML 을 거르고, 걸러진 것을 알린다([공용 코드 규칙의 소개 글의 HTML](shared-code.md#소개-글의-html)).
  - 나이와 성별로 막는 검사는 없다.
- 공개 범위는 비공개와 공개 둘이다. 1~2단계에는 운영자만 만들고, 공개는 운영자의 것만 연다.

## 그림

[배포 설계의 그림 저장소](deployment.md#그림-저장소)에서 정한 것을 asset-server 가 맡는다. #540 의 남은 일(내주는 길, 올리는 규칙, staging 의 버킷과 IAM)이 여기서 끝난다.

**올리기.**

1. 화면이 파일을 asset-server 에 올린다(`POST /api/v1/asset/images`). 서버를 거친다. 브라우저가 저장소에 바로 올리지 않는다. 본문은 파일의 바이트 그대로다(multipart 를 쓰지 않는다. 의존성 하나가 줄고 크기를 읽으면서 자를 수 있다). 프록시의 상한은 11MB 다.
2. 서버가 크기(상한은 설정, 기본 10MB)와 형식(PNG, JPEG, WebP)을 본다. 확장자가 아니라 파일의 머리로 본다.
3. **디코딩을 격리한다.** 그림을 여는 일(크기 확인, 메타데이터 지우기, 다시 인코딩)은 메모리와 시간의 상한을 건 따로 된 프로세스가 한다. 망가진 파일이나 압축 폭탄이 서버를 쓰러뜨리지 않게 한다. 다시 인코딩해서 위치 정보 같은 메타데이터를 지우고, 그림 속에 숨긴 것도 없앤다.
   - 정한 것(2026-10-22): 같은 컨테이너 안의 따로 된 프로세스다(`python -I`, Pillow). 그 프로세스가 주소 공간과 CPU 시간의 상한(`RLIMIT_AS`, `RLIMIT_CPU`)을 스스로 걸고, 서버가 벽시계의 상한을 건다. 한꺼번에 여는 수를 묶는다. 작은 컨테이너로 나누는 것은 올리기가 많아져 한 컨테이너의 메모리가 모자랄 때 본다.
   - 움직이는 그림(애니메이션 WebP, APNG)은 첫 장만 남긴다(유저 결정, 2026-10-22).
4. 저장소(로컬은 SeaweedFS, staging 은 S3)에 그림의 id 로 넣고, 그림의 행(주인, 크기, 형식, 붙은 곳)을 적는다.

**내주기.** `GET /api/v1/asset/images/{id}`

1. nginx 가 받아 asset-server 에 묻는다. asset-server 는 이 사람이 볼 수 있는지(주인이거나, 그림이 붙은 것이 공개이고 등급이 맞는지) 본다.
   "붙은 것"은 게시한 판이다. 게시할 때 그 판에 쓰인 그림(대표 그림과 소개 글의 img)을 `image_uses` 에 적고, 그 판이 공개 캐릭터의 것이고 판의 등급을 볼 수 있으면 남도 본다. 옛 판도 센다(대화가 옛 판을 사본으로 갖고 있다). 그림에 붙은 곳을 한 칸으로 두지 않은 까닭은 한 그림이 여러 판에 쓰이기 때문이다(2026-10-22).
   붙이는 그림은 자기가 올린 것만이다. 남의 그림 id 를 공개 캐릭터에 적어 그 그림을 공개로 돌리는 길을 막는다.
2. 볼 수 없으면(없는 그림 포함) 404 다. 그대로 나간다.
3. 볼 수 있으면 **본문 없이** 아래 두 머리말을 답한다. nginx 가 저장소에서 받아 캐시하고 내준다(`docker/nginx/templates/api.inc.template` 의 `/_images/`).
4. 캐시는 그림의 id 로 찾는다. 그림은 바뀌지 않는다(고치면 새 id). 볼 수 있는지는 캐시가 있어도 요청마다 asset-server 가 본다. 캐시는 바이트만 둔다.

asset-server 와 nginx 의 약속(#566, 2026-10-21 결정):

| 무엇 | 값 | 까닭 |
| --- | --- | --- |
| `X-Accel-Redirect` | `/_images/{id}`. id 는 그림의 UUID(소문자, 붙임표 있음) | nginx 의 내부 위치다. 바깥에서 부르면 404 다 |
| `X-Image-Source` | 저장소의 `GetObject` 를 서명한 주소. 60초 동안 산다 | 키는 asset-server 만 갖는다. nginx 는 받은 주소를 따라가기만 한다. 서명하는 코드가 로컬(SeaweedFS)과 staging(S3)에서 같다 |
| 주소의 범위 | 로컬과 CI 는 `http://object-store:8333/`, staging 은 `https://…s3.<리전>.amazonaws.com/`. 다른 곳이면 nginx 가 502 로 거절한다 | asset-server 가 잘못 적어도 nginx 가 아무 곳에나 요청을 보내지 않게 한다 |
| 형식(`Content-Type`) | 올릴 때 저장소의 객체에 적는다(`image/png`, `image/jpeg`, `image/webp`). nginx 는 저장소가 준 것을 내보낸다 | asset-server 의 답에 적은 형식은 쓰이지 않는다 |
| 저장소가 404, 403 | nginx 가 `{"detail":"찾을 수 없습니다."}` 404 로 답한다. 캐시하지 않는다 | S3 의 XML 과 머리말이 나가지 않는다 |
| nginx 의 캐시 | 디스크, 그림의 id 가 키, 1GB, 7일 동안 안 보면 지운다 | 같은 그림을 S3 에 다시 묻지 않는다. 그림은 바뀌지 않아 틀어질 일이 없다 |
| 브라우저의 캐시 | `Cache-Control: private, max-age=3600` (nginx 가 붙인다) | 공개 그림을 비공개로 돌리면 남의 브라우저에서도 한 시간 안에 막힌다 |
| 사용자의 머리말 | 저장소에 넘기지 않는다(토큰, 쿠키) | 서명한 주소에 `Authorization` 까지 붙으면 S3 가 거절한다. 토큰이 저장소로 새지 않는다 |

asset-server 가 저장소를 읽는 설정(compose 가 넘긴다, `docker-compose.yml` 의 `x-asset-image-store`):

| 이름 | 로컬 | staging |
| --- | --- | --- |
| `IMAGE_STORE_ENDPOINT` | `http://object-store:8333` | `https://s3.<리전>.amazonaws.com` |
| `IMAGE_STORE_REGION` | `ap-northeast-2`(SeaweedFS 는 아무 값이나 받는다) | 루트 `.env` 의 값(서울) |
| `IMAGE_STORE_BUCKET` | `ai-trpg-images` | 루트 `.env` 의 값(그림 버킷) |
| `IMAGE_STORE_ACCESS_KEY_ID`, `IMAGE_STORE_SECRET_ACCESS_KEY` | `ai-trpg-local` 과 루트 `.env` 의 난수 | 그 버킷만 쓰는 IAM 사용자의 키(`docker/object-store/iam-policy.json`) |

서명한 주소는 이 주소로 만든다. nginx 가 그 주소로 받아 가므로, compose 밖에서 띄운 asset-server(`127.0.0.1:8333`)가 만든 주소는 nginx 가 따라가지 못한다. 프록시를 거쳐 내주기를 볼 때는 compose 안에서 띄운다.

## 쓰는 서비스에 내주기

| 길 | 부르는 쪽 | 하는 일 |
| --- | --- | --- |
| 판 가져오기 | chat, story(나중에 TRPG) | 시작할 때 게시된 판 하나의 정의를 받는다. 쓸 수 있는 사람인지는 asset-server 가 판단한다 |
| 페르소나 가져오기 | TRPG, chat, story | 세션을 시작하거나 바꿀 때 페르소나 하나의 사본과 `revision` 을 받는다 |
| 지금의 판과 revision | 셋 모두 | 새 판이나 새 설정이 있는지 묻는다. 화면을 열 때 한 번. 턴마다 묻지 않는다 |

- 서버 사이의 요청은 지금처럼 부르는 서버마다 따로 둔 비밀로 서명한다. 사용자의 토큰을 함께 넘겨 "누구를 위해 가져가는지"를 asset-server 가 본다.
- asset-server 가 죽으면 새 세션을 시작하지 못하고 그림이 안 보인다. 진행 중인 대화와 게임은 사본으로 돈다.

## 데이터의 모양

초안이다. 스키마는 `asset`.

| 테이블 | 주요 칸 | 비고 |
| --- | --- | --- |
| `personas` | `id`, `owner_id`, 이름, 설명, 그림 id, 나이, 성별, 호칭, 말투 예시, 성격, 기본인지, `revision`, 시각 | 판이 없다 |
| `characters` | `id`, `owner_id`, 초안의 칸(이름, 소개 HTML, 인사말, 말투 예시, 나이, 등급, 태그, 시작 상황, 호감도, 의복과 물건, 지도), 공개 범위, 시각 | 초안 |
| `character_versions` | `character_id`, `version`, 게시한 정의(JSON), 게시한 때 | 판. 바뀌지 않는다 |
| `images` | `id`, `owner_id`, 형식, 크기, 너비와 높이, 시각 | 파일은 저장소에 있다 |
| `image_uses` | 판의 id, 그림의 id | 그 판에 쓰인 그림. 판이 지워지면 함께, 쓰인 그림은 지우지 못한다 |

- 정의의 모양(JSON)은 [공용 코드 규칙의 템플릿](shared-code.md#템플릿)과 같게 둔다. 쓰는 쪽이 가져와 검증하는 모양과 같다.
- 지울 때: 계정을 지우면 그 사람의 페르소나, 비공개 캐릭터, 그림을 지운다. 공개한 판을 남이 쓰고 있으면 그 사람의 사본은 남는다(사본이라서). 남긴 공개 캐릭터의 판에 쓰인 그림은 남는다.

## 만드는 순서

조각마다 PR 하나 이상이다.

1. **뼈대.** 폴더, 의존성, 설정, 상태 확인, DB 계정과 스키마(`08-asset-role.sql`), compose 와 프록시의 주소, CI. 인증은 다른 서버처럼 인증 서버의 공개키로 토큰을 본다.
2. **계정 페르소나.** 만들기, 고치기, 지우기, 기본으로 두기, 가져오기(서버 사이). C4 의 서버다.
3. **그림.** 올리기(격리한 디코딩), 내주기(권한 확인과 `X-Accel-Redirect`), nginx 의 내부 위치와 캐시. #540 의 남은 일이 여기서 끝난다.
   PR 둘로 나눈다(유저 결정, 2026-10-22): 먼저 표, 올리기, 저장소, 주인만 보는 내주기. 다음에 페르소나와 캐릭터, 소개 글의 그림이 자기 그림인지 보기, 공개 캐릭터의 그림을 남이 보기, 탈퇴 때 지우기.
4. **캐릭터와 게시.** 초안, 게시와 판, 소개 HTML 거르기(`shared/`), 판 가져오기. C6 의 서버다.
5. **TRPG 의 보관함 나누기.** trpg-server 가 계정 페르소나를 가져오게 하고, 시트를 남기는 이관.
6. **다음.** story 의 세계관(D7 의 서버), TRPG 의 세계관과 로어북 옮기기.

함수는 하나의 책임만 갖는다: `check_image_header`, `decode_isolated`, `store_image`, `can_view`, `accel_redirect`, `publish_version`, `validate_definition`, `sanitize_intro`, `export_version`, `export_persona`.

## 열린 질문

- 그림의 크기 상한과 줄인 그림(목록용 작은 그림)을 올릴 때 만들지, 내줄 때 만들지.
- TRPG 보관함을 나누는 이관의 순서와, 그 사이 TRPG 의 페르소나 화면.
- 판을 내주는 API 의 모양을 템플릿의 정의로 삼을지([공용 코드 규칙의 열린 질문](shared-code.md#열린-질문)).
