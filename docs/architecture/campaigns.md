# 캠페인 설계

TRPG 의 캠페인(#481)의 둘째 단계(B)다. 시나리오 여러 개를 차례로 묶고, 한 편이 끝나면 같은 사람들이 다음 편의 테이블로 캐릭터를 데려간다.
한 시나리오 안에서 잇는 것은 [장 설계](chapters.md)(A)다. 캠페인은 장 위에 얹는다(편 하나하나가 장을 가질 수 있다).

- 정한 날: 2026-11-02(유저 결정)
- 관련: 캐릭터 성장(#286, `trpg-server/README.md` 의 "성장"), 보관함(`trpg-server/README.md` 의 "보관함"), 업적(#193), 퀘스트(`trpg-server/README.md` 의 "퀘스트")

| 무엇 | 정한 것 | 까닭 |
| --- | --- | --- |
| 모양 | 캠페인을 자산으로 둔다. 제작자가 시나리오를 차례로 묶어 게시한다. 한 편이 끝나면 다음 편의 테이블을 같은 사람들과 이어 연다(2026-11-02 유저 결정) | 보관함으로만 옮기면 아무 테이블에나 자란 캐릭터를 들고 갈 수 있어 균형이 깨지고, 앞 편의 결과(퀘스트)를 다음 편이 볼 길이 없다 |

| 판 | 캠페인의 판은 편마다 시나리오의 판 번호를 굳힌다. 한 판(플레이)은 시작할 때의 캠페인 판에 고정한다 | 장(A)의 "테이블은 판에 고정"과 같다. 다음 편을 덧붙인 판은 새로 시작한 플레이만 받는다 |

## 모양

캠페인은 게임 서버(trpg-server)의 자산이다. 룰북, 시나리오와 같이 초안을 고치고 게시하면 판이 생긴다.

```json
{
  "name": "열일곱 행성 추격전",
  "intro_html": "<p>세 편으로 이어지는 추격전.</p>",
  "rating": "all",
  "episodes": [
    { "scenario_id": "<시나리오 1>", "title": "톨게이트" },
    { "scenario_id": "<시나리오 2>", "title": "소행성대" },
    { "scenario_id": "<시나리오 3>", "title": "마지막 행성" }
  ]
}
```

- `episodes` 는 2~10 편이다. 목록의 차례가 편의 차례다. 시나리오는 자기 것이고 게시한 판이 있어야 한다. 같은 시나리오를 두 번 넣지 못한다.
- `title`(30자)은 편의 이름이다. 비우면 시나리오의 이름이다.
- 판에는 편마다 그때의 시나리오의 마지막 판 번호를 굳힌다(`{"scenario_id", "version", "title"}`). 시나리오를 고쳐 다시 게시해도 캠페인을 다시 게시하기 전까지는 앞의 판이다.
- 캠페인의 등급은 편의 등급 가운데 가장 높은 것이다. 공개와 소개는 시나리오와 같은 규칙이다.

## 한 판(플레이)의 흐름

캠페인을 한 번 하는 것을 플레이(`campaign_runs`)라 한다. 플레이는 편마다 테이블 하나를 가진다.

1. **시작.** 방장이 캠페인의 판으로 첫 편의 테이블을 연다. 플레이가 생기고 그 판과 지금 편(1편)을 적는다. 첫 편은 보통의 테이블과 같다(캐릭터를 만들거나 보관함에서 가져온다).
2. **편의 끝.** 테이블이 끝나면(방장이 끝내거나 엔딩) 엔진이 앉은 사람마다 지금 캐릭터의 넘길 것([옮기는 것](#옮기는-것))을 플레이에 적는다(`campaign_carries`). 죽은 캐릭터는 넘기지 않는다.
3. **다음 편.** 방장이 "다음 편"을 누르면 다음 편의 테이블이 같은 판으로 열리고, 앞 편에 앉았던 사람들을 그 자리에 들인다(초대와 같다. 오지 않은 사람은 나중에 들어와도 넘긴 캐릭터를 쓴다).
   넘긴 캐릭터가 있는 사람은 그것으로 앉는다. 없는 사람(죽었거나 새로 온 사람)은 다음 편의 캐릭터 방식대로 새로 만든다.
4. **끝.** 마지막 편이 끝나면 플레이가 끝난다. 넘긴 캐릭터는 보관함에 저장할 수 있다(보관함의 규칙대로, 프리젠은 안 된다).

- 플레이와 편의 테이블은 방장 한 사람이 연다. 방장이 바뀌는 것은 테이블의 방장 넘기기를 따른다.
- 앞 편의 테이블이 끝나지 않았으면 다음 편을 열지 못한다. 한 플레이에 열린 테이블은 하나뿐이다.
- 모델(AI GM)은 플레이와 넘길 것을 바꾸지 못한다. 넘길 것은 엔진이 테이블의 상태에서 적는다.

## 옮기는 것

같은 룰북이라 숫자를 그대로 옮긴다. 다음 편의 테이블에 앉을 때 그 시트를 이것으로 채운다.

| 무엇 | 옮기는 법 |
| --- | --- |
| 능력치 | 앞 편의 시트의 능력치 그대로. 점수제의 총점은 넘어도 된다(성장으로 늘었다). 룰북의 능력치의 범위는 다시 본다 |
| 성장 | 경험치(`xp`), 놓지 않은 능력치 점수(`points`). 레벨은 경험치와 레벨표로 다시 정한다 |
| 최대 HP | 앞 편의 최대 HP 그대로(레벨로 늘어난 몫이 들어 있다). 지금 HP 는 최대로 채운다(편 사이에 쉰다) |
| 소지품 | 물건마다 다음 편의 판에 같은 로어북 물건 항목(`entry_id`)이 있으면 옮긴다. 없으면 옮기지 않고 그 테이블을 시작할 때 알린다(이벤트). 장비의 착용은 풀어서 옮긴다 |
| 돈 | 그대로 |
| 퀘스트 결과 | 플레이가 편마다 이룬 퀘스트와 실패한 퀘스트(사건 항목)를 적는다. 다음 편의 퀘스트와 사건, 장의 조건에 새 종류 `campaign_quest`(앞 편의 퀘스트 하나가 성공했다 / 실패했다)를 쓴다 |

옮기지 않는 것: 부상과 수치의 지금 값(편 사이에 쉰다), 죽음의 굴림, 서 있던 장소, 테이블의 퀘스트·장·시계의 상태(편마다 새로 시작한다), 지난 일(기억).

- 넘길 것은 편이 끝날 때 한 번 적고 바꾸지 않는다. 다음 편에서 자란 것은 그 편이 끝날 때 다시 적는다.
- 프리젠으로 한 캐릭터도 캠페인 안에서는 넘긴다(같은 캠페인 판이라 등급이 맞다). 보관함에는 넣지 못한다.
- 다음 편의 캐릭터 방식(`character_modes`)은 새로 만드는 사람에게만 든다. 넘긴 캐릭터는 방식과 상관없이 앉는다.

## 게시할 때 보는 것

막는 것:

- 편이 둘보다 적다. 같은 시나리오가 두 번 있다
- 내 것이 아니거나 게시한 판이 없는 시나리오가 있다
- 편의 시나리오들의 룰북이 다르다(같은 룰북의 같은 판이어야 한다)
- 조건 `campaign_quest` 가 그 편보다 앞의 편에 없는 퀘스트를 가리킨다

알리는 것:

- 한 편에서 준 물건이 뒤의 편들의 판 어디에도 없다(옮겨지지 않는다)
- 룰북에 성장이 없다(경험치와 레벨이 옮겨지지 않는다)

## 화면

- 만드는 화면: 캠페인 만들기(이름, 소개, 편의 목록과 차례, 게시 점검). TRPG 의 만드는 화면 옆에 둔다.
- 진행: 테이블 방(B6)의 머리에 "2편: 소행성대". 편이 끝나면 방장에게 "다음 편" 단추, 앉은 사람에게 넘긴 캐릭터의 요약(레벨, 물건, 옮겨지지 않은 물건).
- 목록: 내 테이블 목록에 캠페인의 플레이를 한 줄로 묶어 지금 편을 보인다.

## 하지 않는 것

- **story 의 캠페인.** 세계관을 묶지 않는다.
- **다른 룰북 사이의 옮기기.** 같은 룰북만이다.
- **갈림길.** 편은 한 줄이다. 앞 편의 결과로 다음 편을 고르는 것은 그래프형 시나리오(#289)와 함께 정한다.
- **쌓인 능력치 점수를 놓기.** 성장(#286)의 일이다. 캠페인은 놓지 않은 점수를 그대로 옮긴다.
- **진행 중인 플레이를 새 캠페인 판으로 옮기기.** 플레이는 시작할 때의 판에 고정한다.

## 만드는 순서

1. 이 문서.
2. TRPG: 캠페인 자산(초안, 게시, 게시 검사, 판에 편마다 시나리오 판 번호 굳히기).
3. TRPG: 플레이와 넘길 것(편이 끝날 때 적기, 다음 편 테이블 열기, 넘긴 캐릭터로 앉기).
4. TRPG: 조건 `campaign_quest`(퀘스트, 사건, 장).
5. 웹: 캠페인 만들기, 테이블 방의 편 표시와 "다음 편", 목록.

2~5 는 게임 서버를 맡은 쪽이 이 문서를 따른다.
