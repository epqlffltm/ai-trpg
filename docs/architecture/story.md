# story 서버 설계

story 는 `story-server` 가 맡는다(2026-10-21. 그 전에는 `chat-server` 의 두 번째 모드로 두기로 했다). 하나의 세계관 안에서 여러 인물을 만나고, 장소를 옮기고, 이벤트를 겪고, 한 사람에게 고백해 엔딩을 본다. 이 문서는 그 **규칙**을 적는다. 누가 상태를 바꾸는지, 무엇이 언제 일어나는지, 엔진이 무엇을 판정하는지다.

- 기준: `main` `7174728` (2026-10-20)
- chat 과 같은 것(대화 트리, 스트리밍, 과금, 기억, 장소와 소지품, 그림, 성인 등급)은 [chat 서버 설계](chat-server.md)를 따른다. 여기에는 story 에서 다르거나 더해지는 것만 적는다.
- chat-server 와 나눈 선(주소, 포트, 토큰의 대상, 스키마, 가격 이름의 머리)과 함께 쓰는 코드(`shared/server-core`, `shared/ai-core`, `shared/conversation-core`)는 [chat 서버 설계의 story-server 와 나눈 선](chat-server.md#story-server-와-나눈-선)에 있다.
- 화면은 [화면 명세의 D1~D7](../product/screens.md#story-화면의-공통-원칙)에 있다.
- 서버는 뼈대만 있다(`story-server/`, #591). 아래의 규칙은 계획이다.

## 한눈에

- **열린 세계다.** 정해진 줄거리 없이 장소, 인물, 이벤트가 흩어져 있고 조건이 맞으면 열린다. 끝나는 날(D-100 같은 기한)과 장 구조는 제작자가 고르는 옵션이다.
- **결과는 엔진이, 말은 모델이 맡는다.** 이벤트가 열리는지, 호감도가 얼마나 바뀌는지, 고백이 성공하는지, 어느 엔딩인지는 엔진이 제작자가 적은 조건으로 정한다. 모델은 장면 안의 인물들의 말과 서술만 쓴다.
- **상태를 바꾸는 것은 사용자의 행동과 엔진이다.** 이동, 물건 건네기, 시간 보내기, 하루 마치기, 이벤트의 선택지 고르기, 고백이 행동이다. 대화의 내용만으로는 상태가 바뀌지 않는다(chat 과 같다).
- **TRPG 에서 가져온다.** 조건의 모양은 퀘스트의 조건(`QuestConditionKind`, "모두/하나라도")이고, 시각은 게임 안의 시계(#265)이며, 관계 값은 NPC 태도(#474)가 놓인 자리다.

## 정한 것

2026-10-20 에 사용자가 정한 것이다.

| 항목 | 정한 것 | 까닭 |
| --- | --- | --- |
| 뼈대 | 열린 세계가 기본. 기한(D-N)은 제작자가 고르는 옵션. 장(챕터) 구조도 옵션으로 둔다 | 자유 대화와 맞고 만들기가 쉽다. 끝을 원하는 이야기는 기한으로 정한다 |
| 분기 그래프 | story 에 두지 않는다. TRPG 의 그래프형 시나리오(#289)로 남긴다 | 모델이 자유롭게 말하는 의미가 줄어든다 |
| 엔딩을 정하는 것 | 사용자가 고백(행동)으로 한 명을 고르면 엔진이 판정한다. 기한이 있는 이야기에서 기한까지 고르지 않으면 엔진이 자동으로 판정한다 | 결과는 엔진이 정하고, 결정하는 순간은 사용자가 갖는다 |
| 이벤트가 열리는 조건 | TRPG 의 퀘스트 조건 모양(조건 목록과 "모두/하나라도")에 story 의 조건 종류를 더한다 | 표로 고르는 모양이라 제작 도구(D7)와 서버의 검증이 쉽다. TRPG 의 코드와 시험을 가져온다 |
| 이벤트의 몸 | 장면 지시(상황, 나오는 인물, 일러스트)와 제작자가 적은 선택지(0~3개, 선택지마다 효과). 엔진이 효과를 반영하고 모델이 반응을 쓴다 | 여러 인물 사이에서 호감도를 움직이는 주된 길이고, 그 길이 엔진의 손 안에 있다 |
| 여러 인물의 말 | 한 번의 호출로 모델이 장면의 인물을 모두 쓴다. 출력은 인물마다의 말 조각으로 받고 서버가 말하는 사람을 검증한다 | 한 턴 한 청구가 그대로다. 인물끼리 주고받는 맛이 남는다 |
| 인물의 위치 | 기본은 고정 장소. 필요한 시간대만 일정으로 덮어쓴다. 이벤트의 효과로 동행(데리고 다니기)을 시작하고 끝낸다 | 처음에는 고정만큼 쉽고, 원하는 만큼만 일정을 쓴다 |
| 시각 | 이동에 걸리는 시간, "시간 보내기"(다음 시간대), "하루 마치기"(다음 날)로만 흐른다 | 시간이 넘어가는 것이 대화의 길이에 기대지 않고 사용자의 행동이 된다 |
| 다시 하기 | 새로 시작하면 새 세션이 생긴다. 지난 세션은 목록에 남고 언제든 이어서 한다 | 잘못 눌러도 잃지 않는다. chat 도 같다 |
| 플레이 복사 | 지금까지의 플레이를 복사해 새 세션을 만드는 기능은 나중(2단계 이후)에 넣는다. 넣을 수 있는 모양만 지킨다 | 한 세션 안의 트리(다시 생성, 앞 가지로 돌아가기)로 1단계는 막히지 않는다 |
| 호감도 | 인물마다 숫자 하나(0~100)와 단계 이름(경계값은 제작자가 정한다). 여러 축과 인물끼리의 영향은 나중에 제작자가 쓸 수 있게 틈을 둔다([호감도](#호감도)) | chat 의 규칙과 표시를 그대로 쓴다 |
| 고백의 성공 | 그 인물의 호감도가 정한 단계 이상이고, 제작자가 적은 조건 목록(이벤트를 봤다 등)을 채웠다 | "이 장면을 봐야 한다"를 정할 수 있다 |
| 엔딩의 모양 | 제작자가 자유롭게 적는 목록. 엔딩마다 무엇으로 시작되는지(고백, 기한, 이벤트)와 조건 목록을 적고, 앞에 적은 것부터 맞춰 본다 | 인물마다의 여러 엔딩, 솔로 엔딩, 이벤트로 끝나는 엔딩을 한 규칙으로 담는다 |
| 고백의 실패 | 제작자가 인물마다 고른다. 이야기를 계속하거나(기본) 실패 엔딩으로 끝낸다 | 이야기의 성격에 맞춘다 |
| 엔딩 뒤 | 제작자가 세계관마다 고른다. 끝(읽기만) 또는 후일담. 후일담에서는 모든 행동이 되고 엔딩과 기한만 다시 일어나지 않는다([세션과 기록](#세션과-기록)) | 이야기마다 여운의 모양이 다르다 |
| 보이기 | 인물의 공개(보임, 실루엣, 숨김), 지도에 인물을 보이는지(보임, 숨김, 호감도 단계 이상), 인물 창의 항목은 제작자가 정한다. 세계관마다의 기본에 인물마다 덮어쓴다 | 제작자의 의도를 따른다. 지도와 인물 창이 한 가지 방식으로 된다 |
| 행동과 반응 | chat 처럼 한 번에 받는다. 행동(이동, 시간, 선택지, 고백) 하나를 SSE 로 받아 엔진이 반영하고 바로 모델의 반응을 스트리밍한다(2026-10-25) | chat 과 화면의 코드가 같다. 행동마다 따로 "이어서 생성"을 누르지 않는다 |
| 말 조각의 모양 | 줄 머리의 표식. 모델이 `@인물:` `@narration:` 처럼 줄 머리에 적고, 서버가 흘러오는 대로 잘라 말하는 사람을 검증한다. 표식을 어긴 줄은 서술로 돌린다(2026-10-25) | 공급자와 상관없이 되고, 스트리밍 중에 이름표가 바로 바뀐다. JSON 줄은 모델이 틀리기 쉽고 반쯤 온 줄을 보이기 어렵다 |
| 청구 | 결제 서버에 story 전용 서명 비밀(`STORY_SERVER_SECRET`)과 가격 머리(`story`)를 둔다(2026-10-25) | 한 서버의 비밀이 새도 다른 서버의 값으로 크레딧을 빼지 못한다. chat 서버에 붙어 있던 `story` 머리를 story 서버로 옮겼다 |
| 모델 목록 | chat 처럼 모델 목록의 원본 파일(`ai_core/model_catalog.toml`)을 story 의 표로 들여오고 세션마다 모델을 고른다(2026-10-25) | chat 의 코드와 운영(켜기, 성인 스위치)을 그대로 쓴다 |
| 소개 글 | HTML 과 인라인 CSS 로 자유롭게. 그림도 넣는다. 게시할 때 서버가, 그릴 때 화면이 거른다([공용 코드 규칙의 소개 글의 HTML](shared-code.md#소개-글의-html)) | 다른 서비스들이 그렇게 한다. 세 서비스가 같은 규칙을 쓴다 |

## 기본값으로 둔 것

사용자에게 묻지 않고 정한 값이다. 바꿀 수 있게 설정이나 제작 칸으로 둔다.

| 항목 | 기본값 | 까닭 |
| --- | --- | --- |
| 장면의 인물 수 | 이름 있는 인물 4명까지 | 프롬프트의 길이와 말투가 섞이는 것을 생각한 값. 실측 뒤 고친다 |
| 시간대 | 이야기마다 제작자가 정한다. 기본은 아침, 낮, 저녁, 밤 | chat 의 배경이 시간대마다다. 같은 목록을 쓴다 |
| 고백의 실패 처리 | 계속. 그 인물의 호감도가 제작자가 정한 만큼 내려가고, 정한 시간(기본 하루) 동안 다시 고백하지 못한다 | 열린 세계에서 한 번의 실수로 끝나지 않게 |
| 엔딩 뒤 | 끝(읽기만). 제작자가 후일담을 고를 수 있다 | 엔딩 뒤에 상태가 바뀌면 기록과 어긋나기 쉽다 |
| 이벤트가 여럿 열릴 때 | 제작자가 적은 차례로 하나만 연다. 나머지는 다음에 다시 본다 | 한 장면에 이벤트가 겹치면 모델의 지시가 엉킨다 |
| 이벤트의 되풀이 | 한 번만. 제작자가 "되풀이"를 고를 수 있다 | 대부분의 이벤트는 한 번 보는 장면이다 |

## 권한의 선

| 값 | 원본 | 바꾸는 것 |
| --- | --- | --- |
| 세계관, 인물, 장소, 이벤트, 엔딩의 정의 | asset-server. 세션에는 시작할 때 고정한 복사본 | 읽기만 한다 |
| 장소, 시각(날짜와 시간대), 소지품, 동행 | DB(메시지에 붙은 상태) | 사용자의 행동을 엔진이 검증해 반영 |
| 인물마다의 호감도 | DB(메시지에 붙은 상태) | 행동(선물)과 이벤트의 효과를 엔진이 반영 |
| 본 이벤트, 고백 대기 | DB(메시지에 붙은 상태) | 엔진 |
| 엔딩 | DB(세션과 계정의 기록) | 엔진이 판정 |
| 말과 서술 | 모델의 출력 | 모델. 서버가 말하는 사람을 검증한다. 상태는 바꾸지 못한다 |

모델의 출력은 상태가 아니다. 모델이 "아리가 반지를 받았다"고 써도 소지품은 바뀌지 않는다. 바뀌는 것은 사용자가 소지품에서 반지를 건넸을 때뿐이다.

## 뼈대

- **열린 세계(기본).** 시작 장소와 시작 소지품에서 시작한다. 정해진 줄거리가 없다. 엔딩은 고백이나 이벤트로 시작된다.
- **기한(옵션).** 제작자가 날 수(D-N)를 적으면 마지막 날의 마지막 시간대가 지날 때 "기한" 엔딩을 판정한다. 화면은 남은 날을 보인다.
- **장 구조(옵션, 나중).** 장마다 열리는 장소와 이벤트를 나누고, 장을 넘기는 조건을 적는다. TRPG 의 캠페인(#481)은 아직 없다. 두 뜻(한 시나리오 안에서 차례로 잇기, 시나리오 여러 개를 묶기) 가운데 story 의 장은 앞의 것에 가깝다. #481 을 정할 때 TRPG 와 story 가 같은 모양을 쓰게 함께 정한다. 1단계에는 넣지 않는다.
- **분기 그래프는 두지 않는다.** TRPG 의 그래프형 시나리오(#289)의 일이다.

## 시각

- 날짜(1일째부터)와 시간대(제작자가 정한 목록)로 센다. TRPG 의 게임 안 시계(#265)와 chat 의 시간대를 쓴다.
- 시각은 1일째 0시부터 흐른 분 하나로 둔다(chat 과 같다). 날짜는 자정에 바뀌고, 첫 시간대가 시작하기 전(새벽)은 마지막 시간대가 이어진다. 기한이 N일이면 N+1일째가 된 때 지났다.
- 흐르는 길은 셋뿐이다.

| 행동 | 흐름 |
| --- | --- |
| 이동 | 길에 적은 시간만큼. 시간대의 경계를 넘으면 시간대가 바뀐다 |
| 시간 보내기 | 다음 시간대로. 마지막 시간대면 하루 마치기와 같다 |
| 하루 마치기 | 다음 날의 첫 시간대로. 자정을 넘겨 그날의 첫 시간대가 아직 오지 않았으면 그날의 첫 시간대로 |

- 모두 행동 말(`role` = `action`)이다. 행동 자체는 모델을 부르지 않아 청구하지 않는다. 이어서 반응을 생성하면 한 번의 말로 청구한다(chat 과 같다).
- 상태는 메시지에 붙으므로 다시 생성이나 앞 가지로 돌아가면 시각도 그 가지의 것이 된다.
- 시각이 바뀌면 엔진이 인물의 위치, 이벤트, 기한을 다시 본다.

## 인물과 장면

**인물이 어디에 있는가.** 엔진이 정한다. 높은 것부터 본다.

1. **동행 중**이면 사용자와 같은 곳.
2. **일정**에 지금의 시간대(와 조건)에 맞는 줄이 있으면 그 장소. 일정의 줄은 (시간대, 장소, 조건 목록)이다. 조건은 [조건](#조건)의 모양이라 "3일째부터", "그 이벤트를 본 뒤"를 적을 수 있다. 위에 적은 줄부터 맞춰 본다.
3. 아니면 **기본 장소**. 비워 두면 어디에도 없다(이벤트로만 나온다).

**장면의 인물.** 사용자가 있는 장소에 있는 인물이다. 열린 이벤트가 인물을 부르면 그 인물도 들어온다. 상한(4명)을 넘으면 동행, 이벤트, 일정, 기본 장소의 차례로, 같은 차례에서는 제작자가 적은 인물의 차례로 고른다. 장면의 인물 목록은 응답마다 메시지의 상태와 함께 남는다.

**동행.** 이벤트의 효과로 시작하고 끝낸다. 동행 중인 인물은 이동할 때 함께 옮긴다. 일정보다 앞선다.

## 한 번의 말

chat 의 [한 번의 말이 지나가는 길](chat-server.md#한-번의-말이-지나가는-길)과 같고, 다른 것은 말하는 사람이 여럿이라는 것이다.

- 프롬프트에 장면의 인물들(설정, 말투, 지금의 호감도 단계)과 열린 이벤트의 장면 지시가 들어간다. 장면 밖의 인물은 들어가지 않는다.
- 모델은 **말 조각의 목록**을 낸다. 조각마다 말하는 사람(장면의 인물 id 또는 서술)과 글이다.
- 서버는 말하는 사람이 장면의 인물이거나 서술인지 검증한다. 장면에 없는 인물의 조각은 버리고 기록한다(`generations` 에 어긋난 수). 모든 조각이 버려지면 실패한 말이 되고 청구하지 않는다(chat 의 실패와 같다).
- 화면은 조각마다 이름표와 캐릭터 그림을 바꾼다. 서술은 이름표가 없다.
- 호출은 한 번, 청구도 한 번이다. 인물마다 따로 부르지 않는다.
- 스트리밍 중에 조각은 줄 머리의 표식(`@인물:`, `@narration:`)으로 나눈다([정한 것](#정한-것)). 표식을 어긴 줄은 서술로 돌린다.

## 이벤트

이벤트는 세계관 자체의 목록이다(2026-10-24 유저 결정). 처음에는 TRPG 처럼 "로어북의 사건 항목 하나와 그 규칙"으로 적었으나, asset 의 로어북은 세계관과 따로 된 자산이라 이벤트 하나를 두 곳에서 고치게 되어 바꿨다. 설정을 찾는 로어북은 세계관이 따로 가리킨다.

| 칸 | 뜻 |
| --- | --- |
| 열리는 조건 | 조건 목록과 맞추는 법(모두/하나라도). [조건](#조건) |
| 되풀이 | 한 번만(기본) 또는 되풀이 |
| 장면 지시 | 모델에게 주는 상황 설명. 나오는 인물(장면에 불러들인다). 일러스트(있으면 그림 창의 배경과 캐릭터를 대신한다) |
| 열릴 때의 효과 | 열리자마자 엔진이 반영하는 것. [효과](#효과) |
| 선택지 | 0~3개. 선택지마다 글과 효과 목록 |

**흐름.**

1. 행동(이동, 시간, 건네기, 선택지, 고백) 뒤에 엔진이 열 수 있는 이벤트를 본다. 열리면 열릴 때의 효과를 반영하고 "본 이벤트"에 넣는다.
2. 이어지는 응답은 장면 지시를 받아 그 장면을 쓴다. 선택지가 있으면 화면이 응답 밑에 선택지를 보인다. 이것은 모델이 낸 다음 답 추천이 아니라 제작자가 적은 고정된 선택지다.
3. 사용자가 선택지를 고르면 행동 말이 되고, 엔진이 그 선택지의 효과를 반영한다. 이어서 모델이 그 선택에 대한 반응을 쓴다(한 번의 말, 한 번 청구). 선택지를 고르지 않고 말을 이어도 된다. 그때 선택지는 사라지고 효과는 없다.
4. 선택지가 없는 이벤트는 장면 지시만 있다.

- 이벤트 하나에 응답이 둘(장면, 선택의 반응)이라 청구도 둘이다. 선택지가 없으면 하나다.
- 다시 생성해도 이벤트는 다시 열리지 않는다. 열린 것은 그 가지의 상태에 있다.

## 조건

TRPG 의 퀘스트 조건과 같은 모양이다. 조건 하나는 (종류, 대상, 값)이고, 목록을 "모두" 또는 "하나라도"로 맞춘다. 엔진이 이미 아는 사실만 본다. 이벤트가 열리는 조건, 일정의 줄, 고백의 성공 조건, 엔딩의 조건이 모두 이 모양을 쓴다.

| 종류 | 뜻 | TRPG 에서 |
| --- | --- | --- |
| 장소에 있다 | 사용자가 그 장소에 있다 | `reach_place` |
| 물건을 가졌다 | 그 물건을 count 개 이상 가졌다 | `hold_item` |
| 이벤트를 봤다 | 그 이벤트가 열린 적이 있다 | `quest_succeeded` 와 같은 자리(퀘스트 잇기) |
| 물건을 건넸다 | 그 인물에게 그 물건을 건넨 적이 있다 | 새로 |
| 호감도 단계 | 그 인물의 호감도가 그 단계 이상(또는 이하) | 새로 |
| 날짜 | n일째 이상, 이하 | 새로 |
| 시간대 | 지금의 시간대가 그것이다 | 새로 |
| 동행 중 | 그 인물과 동행 중이다 | 새로 |

- 조건을 맞추는 함수는 story 안에 둔다(`story-server/app/engine/conditions.py`). TRPG 의 퀘스트 조건(`trpg-server` 의 `app/rounds/quest_goals.py`)과 `shared/` 로 뽑아 함께 쓰려 했으나 뽑지 않았다(2026-10-25).
  종류가 겹치지 않고(story 는 호감도, 날짜, 동행, TRPG 는 몬스터, 퀘스트 잇기) 빈 목록의 뜻이 반대다(story 는 늘 맞음, TRPG 는 이루지 않음). 함께 쓸 수 있는 것은 "모두/하나라도"를 고르는 한 줄뿐이다.
- 회차 혜택(이 엔딩을 본 적이 있다)은 조건이 세션 밖(계정)을 보게 되어 지금은 넣지 않는다([열린 질문](#열린-질문)).

## 효과

이벤트가 열릴 때, 선택지를 고를 때 엔진이 반영하는 것이다. 목록이고 차례대로 반영한다.

| 효과 | 뜻 |
| --- | --- |
| 호감도 바꾸기 | 그 인물의 호감도를 +n, -n. 한 효과 목록에 여러 인물을 함께 적을 수 있다(질투 같은 것) |
| 물건 주기, 가져가기 | 사용자의 소지품 |
| 동행 시작, 끝 | 그 인물 |
| 장소 옮기기 | 사용자(와 동행)를 그 장소로. 시간은 흐르지 않는다 |
| 일러스트 열기 | 해금 대상이면 계정에 기록한다(story 스키마의 `illustration_unlocks`. chat 의 표와 같은 모양이고 따로 둔다. 갤러리는 서비스마다 탭이다, #593). 효과의 목록에 적지 않고 이벤트의 장면 칸(`collectible`)으로 둔다. 일러스트는 장면에 붙어 있고, 열리면 그 장면의 것을 연다(2026-10-24) |

- 값은 범위(0~100) 안으로 자른다.
- 효과는 엔진만 반영한다. 모델의 글에는 효과가 없다.

## 호감도

- 인물마다 숫자 하나(0~100)와 단계 이름이다. 단계의 경계값과 이름, 보이는 방식(숫자와 게이지, 단계 이름과 게이지)은 제작자가 정한다. chat 의 호감도와 같다.
- 바뀌는 길은 둘이다. 물건을 건넬 때 제작자가 적은 규칙(chat 과 같다), 그리고 이벤트의 효과. 대화의 내용만으로는 움직이지 않는다(첫 출시).
- **여러 축을 위한 틈.** 값을 "관계 값의 이름 → 숫자"로 저장한다. 처음에는 이름이 `affection` 하나뿐이다. 조건과 효과는 관계 값의 이름을 받는다. 제작자가 신뢰, 긴장 같은 축을 더하는 날에는 이름을 더하고 표시만 늘리면 된다. 데이터를 옮기지 않는다.
- **인물끼리의 영향을 위한 틈.** 지금은 한 효과 목록에 여러 인물을 적어 표현한다. 따로 규칙("A 의 호감도가 오르면 B 가 내린다")을 쓰고 싶어지면, 호감도가 바뀐 뒤 엔진이 보는 "반응 규칙"(조건 목록과 효과 목록)을 더한다. 조건과 효과의 모양이 그대로라 새 종류가 아니라 새 자리 하나다. 되풀이로 끝없이 도는 것을 막는 상한을 그때 함께 정한다.
- 모델이 호감도의 변화를 제안하는 단계는 chat 과 함께 나중이다.

## 고백과 엔딩

**고백.** 장면에 있는 인물 하나를 골라 하는 행동이다. 대기 중인 인물에게는 할 수 없다.

1. 엔진이 그 인물의 **고백의 성공 조건**을 본다. 호감도가 정한 단계 이상이고 조건 목록을 채웠으면 성공이다.
2. 성공이면 "그 인물에게 고백 성공"으로 시작되는 엔딩을 판정한다.
3. 실패면 그 인물에 정한 대로 한다.
   - 계속(기본): 호감도를 정한 만큼 내리고, 정한 시간 동안 다시 고백하지 못한다(고백 대기). 반응은 모델이 쓴다.
   - 끝: "그 인물에게 고백 실패"로 시작되는 엔딩을 판정한다.

**엔딩.** 제작자가 적는 목록이다.

| 칸 | 뜻 |
| --- | --- |
| 이름 | 엔딩 목록(D6)에 보이는 이름 |
| 시작 | 무엇으로 판정이 시작되는가. 그 인물에게 고백 성공 / 그 인물에게 고백 실패 / 기한 / 그 이벤트 |
| 조건 | 조건 목록. 비우면 늘 맞는다 |
| 장면 지시와 일러스트 | 엔딩의 장면. 모델이 쓴다 |
| 해금 | 계정의 엔딩 기록과 갤러리에 남기는가 |

- **판정.** 시작이 일어나면, 그 시작의 엔딩을 제작자가 적은 차례로 위에서부터 맞춰 보고 처음 맞는 것 하나를 고른다. TRPG 의 퀘스트를 판의 차례로 보는 것과 같다.
- **빠짐이 없게.** 쓰인 시작마다 조건이 빈 엔딩이 하나는 있어야 게시된다. 고백에 성공했는데 맞는 엔딩이 없는 일을 asset-server 가 게시할 때 막는다.
- **기한.** 기한이 있는 이야기에서 마지막 날의 마지막 시간대가 지나면 "기한" 엔딩을 판정한다(솔로 엔딩 같은 것). 기한이 없는 이야기는 고백이나 이벤트로만 끝난다.
- 엔딩의 장면은 한 번의 말(한 번 청구)이다. 그 뒤는 세계관에 정한 대로 세션이 끝나거나 후일담이 된다([세션과 기록](#세션과-기록)).

## 세션과 기록

- 세계관 하나를 새로 시작하면 새 세션(`story.conversations` 의 행)이 생긴다. 지난 세션은 목록에 남고 언제든 이어서 한다. 화면의 이어하기(A1)와 목록(D1)이 읽는다. 목록의 모양은 chat 의 대화 목록과 같다(`?limit=&offset=`, 마지막 말이 최근인 것부터, 세계관으로 거르기. #593).
- 한 세션 안에서는 chat 처럼 트리다. 다시 생성, 고치기, 앞 가지로 돌아가기가 되고, 상태는 가지마다다.
- **플레이 복사(나중).** 지금 보고 있는 가지의 말과 상태를 새 세션에 복사한다. 상태가 메시지에 붙어 있어 가지 하나를 복사하면 끝난다. 그때 고칠 것은 복사한 세션의 청구 기록을 어떻게 볼지뿐이다(다시 청구하지 않는다).
- **엔딩 뒤.** 제작자가 세계관마다 고른다.
  - 끝(기본): 세션은 끝난 세션이 된다. 읽기와 그림 다시 보기만 된다. 서버는 행동 말과 말을 받지 않는다.
  - 후일담: 세션이 후일담이 된다. 말과 행동(이동, 건네기, 시간, 선택지)이 모두 되고 말마다 청구한다. 이벤트도 열리고 일러스트도 열린다. 엔딩과 기한만 다시 일어나지 않는다. 그래서 후일담에서는 고백을 받지 않는다. 본 엔딩의 기록은 엔딩 때의 것 그대로고, 그 뒤의 상태는 기록과 상관없다.
- **계정의 기록.** 본 엔딩(`ending_records`)과 연 일러스트(`illustration_unlocks`)는 계정에 남는다. 세션을 지우거나 가지를 바꿔도 남는다. 엔딩 목록(D6)과 갤러리가 읽는다.

## 데이터의 모양

초안이다. 모든 표는 `story` 스키마에 둔다. 대화, 메시지, 메시지의 공통 상태(장소, 시각, 소지품)는 chat 과 같은 모양의 표를 이 스키마에 따로 둔다(코드는 `shared/conversation-core`. [나눈 선](chat-server.md#story-server-와-나눈-선)). 아래는 story 에만 있는 표다.

| 테이블 | 주요 칸 | 비고 |
| --- | --- | --- |
| `story.worlds` | `id`, `owner_id`, `source_id`(asset-server 의 세계관 id), `version`(판의 번호), 이름, 등급, `document`(판의 문서. 시간대, 지도, 물건, 인물, 이벤트, 엔딩을 받은 그대로) | 세션을 시작할 때 가져와 고정한 복사본. 사람마다, 판마다 하나다(chat 의 캐릭터 사본과 같다). 인물, 이벤트, 엔딩을 표로 쪼개지 않는다(2026-10-24) |
| `story.conversations` | `id`, `owner_id`, `world_id`(판의 사본), 제목, 시각 | 세션 하나. 말과 말에 붙는 상태는 만드는 순서 2 부터 더한다 |
| `story.message_states` | `message_id`, `state`(엔진의 상태 전체: 시각, 장소, 소지품, 호감도, 건넨 물건, 본 이벤트, 동행, 고르기를 기다리는 이벤트, 고백 대기, 본 엔딩) | 상태가 바뀐 말에만. 칸으로 나누지 않고 JSONB 하나로 둔다(2026-10-25). 엔진이 늘 상태 전체를 읽고 쓴다. 장면의 인물은 답(`messages.cast`)에 남는다 |
| `story.ending_records` | `owner_id`, `world_source`, `ending_id`, 처음 본 시각, 본 세션 | 계정의 기록 |
| `story.illustration_unlocks` | `owner_id`, `character_source`, `illustration_id`, 처음 연 시각(chat 의 표와 같은 칸) | 계정의 기록. 갤러리의 story 탭(C7)이 읽는다. chat 의 표에 쓰지 않는다(#593) |

- **판의 사본을 표로 쪼개지 않는다(2026-10-24).** 판은 바뀌지 않고, 엔진은 턴마다 판 전체(인물, 이벤트, 엔딩)를 읽는다.
  표로 쪼개면 asset-server 의 형식이 바뀔 때마다 두 서버의 표를 함께 고쳐야 하고, 읽을 때마다 여러 표를 모아야 한다.
  인물이나 이벤트로 찾는 일이 생기면 그때 그 칸만 꺼내는 색인을 더한다.
- 세계관, 인물, 이벤트, 엔딩의 원본은 asset-server 다. 판의 모양은 asset-server 의 세계관(`asset-server/README.md` 의 "세계관")에 있다. 인물은 캐릭터를 가리키고 게시할 때 캐릭터의 판에서 story 에 쓰는 칸만 복사한다(2026-10-24 유저 결정).
- 시간대는 이름과 시작 시각(몇 시)이다. 이동이 길의 분만큼 시각을 흘리고, 시각이 다음 시간대의 시작을 넘으면 시간대가 바뀐다. 시간 보내기는 다음 시간대의 시작으로 간다.
- 세션의 끝(엔딩)과 후일담인지는 공통 모양의 `conversations` 에 칸을 더하지 않고 따로 둔다(세션 id → 본 엔딩, 진행 / 끝 / 후일담). 공용 코드가 story 만의 개념을 모르게 하려는 것이다.

## 만드는 순서

chat 의 [만드는 순서](chat-server.md#만드는-순서) 1~5(대화, 한 번의 말, 조작, 가져오기, 장소와 소지품)가 먼저다(했다). 그 위에 다음 차례로 쌓는다. 조각마다 PR 하나 이상이다.

0. **준비.** `shared/server-core` 위에 `story-server` 의 뼈대(했다, #591. 설정, 로그, 추적, 메트릭, 상태 확인, 토큰 검증, Alembic, CI), compose 와 프록시에 붙이기(했다. DB 계정의 초기화 스크립트 `10-story-role.sql`, 대시보드와 경보를 함께), asset 의 세계관 자산(했다. 판의 모양과 게시 검사, story 에 내주는 길), chat 의 대화 핵심을 `shared/conversation-core` 로 옮기기.

1. **세계관과 세션.** 판 가져오기(인물, 장소, 이벤트, 엔딩), 세션 만들기와 목록(했다. 판의 문서는 받은 그대로 사본에 두고, 칸을 읽는 모양은 그 칸을 쓰는 조각이 더한다).
2. **장면의 인물.** 기본 장소, 일정, 동행의 위치 계산(했다. 엔진의 순수 함수, `story-server/app/engine/scene.py`). 여러 인물의 말(말 조각, 말하는 사람 검증).
   말을 주고받는 조각은 chat 의 한 번의 말처럼 PR 넷으로 나눈다: 모델 목록과 세션의 모델(했다), 결제 서버를 부르는 것(story 전용 비밀과 머리. 했다. 모델 목록에 값이 붙고 팔지 않는 모델은 고르지 못한다), 행동과 말을 보내는 SSE(상태의 저장, 말 조각. 말 보내기를 했다. 행동은 다음이다), 다시 생성과 멈추기.
3. **시각.** 이동, 시간 보내기, 하루 마치기, 기한(했다. 엔진의 순수 함수, `story-server/app/engine/clock.py`, `actions.py`). 기한이 지났을 때의 엔딩은 5 다.
4. **조건과 효과.** 조건 맞추기, 효과, 이벤트가 열리기, 선택지(했다. 엔진의 순수 함수, `story-server/app/engine/conditions.py`, `effects.py`, `events.py`).
5. **고백과 엔딩.** 고백 대기, 엔딩 판정(했다. 엔진의 순수 함수, `story-server/app/engine/confession.py`, `endings.py`), 게시 때의 빠짐 검사(했다, asset). 계정의 기록은 말을 주고받는 조각에서 한다.
6. **제작 도구(D7).** 운영자가 쓸 만큼(PC 폼).

함수는 하나의 책임만 갖는다: `place_of_character`, `scene_cast`, `move_to`, `pass_time`, `end_day`, `match_conditions`, `open_events`, `apply_effects`, `check_confession`, `pick_ending`, `validate_speakers`.
엔진(`story-server/app/engine/`)은 판과 상태만 받는 순수 함수다. DB 와 모델을 모른다. 세션과 말에 붙이는 일은 말을 주고받는 조각에서 한다.

## 열린 질문

- 조각이 반쯤 왔을 때(표식의 줄 머리가 아직 다 오지 않았을 때) 화면이 이름표를 언제 바꾸는지.
- 장 구조의 모양. TRPG 의 캠페인(#481)과 함께 정한다.
- 이벤트의 장면과 선택의 반응이 둘로 청구되는 것이 비싸게 느껴지는지. 실측 뒤 한 번으로 묶을지 본다.
- 회차 혜택(이 엔딩을 본 적이 있다는 조건). 계정의 기록을 조건이 보게 할지.
- 반응 규칙(인물끼리의 영향)과 여러 축을 켤 때의 표시(D5).
- 장면의 인물 상한(4명)이 모델마다 맞는지. 실측한다.
