# 공통 규격의 시험 파일

언어가 다른 서버들이 같은 규칙을 지키는지 보는 시험 파일이다(#786). 코드는 언어가 달라 나눌 수 없어서, 입력과 기대 결과만 JSON 으로 나눈다.
같은 파일을 세 쪽의 테스트가 읽는다. 한 쪽이 어긋나면 그 쪽의 CI 가 떨어진다.

| 파일 | 규칙 | 읽는 테스트 |
| --- | --- | --- |
| `service-signature.json` | 서버끼리의 서명(`X-Service-Signature`) | `shared/server-core/tests/test_contracts.py`, `auth-server/accounts/tests/test_contracts.py`, `billing-server/internal/serviceauth/contract_test.go`, `board-server/tests/test_contracts.py`(게시판은 머리말을 읽는 법을 따로 둔다) |
| `redaction.json` | 로그에 적기 전에 가리는 칸과 글 | 공용 코드, 인증 서버(위와 같은 파일), 결제 서버(`billing-server/internal/obs/contract_test.go`) |
| `access-tokens.json` | 인증 서버의 access 토큰을 받는 쪽의 검증 | `shared/server-core/tests/test_contracts.py`, `billing-server/internal/auth/contract_test.go`. 인증 서버는 토큰을 내는 쪽이라 읽지 않는다 |

이 폴더가 바뀌면 관문(`.github/scripts/changed-servers.sh`)이 공용 코드, 인증, 게시판, 결제의 CI 를 고른다.
공용 코드를 쓰는 다른 Python 서버(trpg, chat, story …)는 공용 코드의 서명과 가리기를 그대로 쓰므로 따로 읽지 않는다.

## 고치는 법

- `redaction.json` 은 손으로 적는다. 기대값이 계산이 아니라 정한 규칙이다.
- `service-signature.json` 과 `access-tokens.json` 은 `generate.py` 가 만든다. 손으로 고치지 않는다.

  ```
  cd shared/server-core; uv run python ../contracts/generate.py
  ```

  - 서명은 서버의 코드가 아니라 표준 라이브러리의 HMAC 으로 직접 계산한다. 서버의 코드로 기대값을 만들면 틀린 코드가 스스로를 맞다고 하게 된다.
  - 토큰은 돌릴 때마다 새 RSA 키로 서명하고, 공개키(JWKS)와 토큰만 적는다. 개인키는 어디에도 적지 않는다. 경우 하나를 고치려면 모두 다시 만든다.
  - 토큰의 만료는 2100년, 발급은 2020년이다. 받는 쪽은 진짜 지금 시각으로 본다. 2100년이 되기 전에 다시 만든다.
- 규칙을 바꾸면 세 쪽의 코드를 함께 고친다. 한 쪽만 고치면 나머지 둘의 CI 가 떨어진다. 그것이 이 파일의 일이다.

## 정한 규칙

처음 맞춰 볼 때(2026-11-02) 서버마다 달랐던 것을 아래로 맞췄다.

### 서명

- 머리말은 `t=<시각>,v1=<서명>` 하나뿐이다. 시각은 앞에 0 이나 부호가 없는 10진수, 서명은 16진수 소문자 64자다.
  대문자 16진수(결제 서버만 받았다), `+170…`(결제 서버만 받았다), `0170…`(공용 코드와 결제 서버가 받았다)은 받지 않는다.
  비밀을 모르면 어느 모양으로도 서명을 꾸밀 수 없어 위험은 아니었지만, 같은 요청을 서버마다 다르게 받으면 안 된다.
- 시각은 지금에서 앞뒤 5분(300초)까지 받는다. 경계(300초)는 받는다.
- 비밀이 32자보다 짧으면 맞는 서명도 받지 않는다.

### 로그 가리기

- `Bearer`, `Basic` 의 앞은 ASCII 의 낱말 글자(영문, 숫자, 밑줄)가 아니면 된다. 한글 바로 뒤의 `Bearer …` 도 가린다(공용 코드와 인증 서버는 가리지 않았다).
- `Bearer` 와 값 사이의 빈칸은 유니코드의 빈칸이다. `Bearer …`(줄바꿈 없는 빈칸)도 가린다(결제 서버는 가리지 않았다).
- 주소의 계정이 비어 있어도(`redis://:비밀번호@호스트`) 비밀번호를 가린다(셋 다 가리지 않았다. 실제로 새던 모양이다).
- 칸의 이름을 낱말로 쪼개 보는 규칙, 자르기를 먼저 하는 것(잘려서 짧아진 토큰은 가리지 않는다)은 그대로다.
- 정하지 않은 것: 주소의 계정에 유니코드 빈칸이 든 경우. 서버마다 다를 수 있다. 실제로 생기면 경우를 더하고 맞춘다.

### access 토큰

- 세션 버전(`ver`)이 음수인 토큰은 거부한다(결제 서버는 받았다. 끊긴 세션의 목록에 없는 사람이면 통했다).
- 발급 시각(`iat`)이 미래인 토큰은 거부한다(결제 서버는 받았다). 서버끼리의 시계 차이 10초는 봐준다.
- 성인용(`adult_content`)과 운영자(`roles`)는 공용 코드만 읽는다. 결제 서버는 보지 않는다.
- 끊긴 세션의 목록과 키 목록을 받아 오는 일은 이 파일이 보지 않는다. 서버마다의 테스트가 본다.
